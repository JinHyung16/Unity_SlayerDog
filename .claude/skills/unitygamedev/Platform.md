# Platform — 플랫폼 · 입력 · 해상도 · 빌드 설정

> [확정표 3·8] 이 이 문서의 값을 정한다. 성능 «기법»은 `Optimize.md`, 여기는 «목표와 계약»이다.

## 플랫폼은 「어디서 도나」가 아니라 「무엇이 제약인가」다

| 플랫폼 | 지배 제약 | 여기서 갈리는 것 |
|---|---|---|
| 모바일 | **발열·배터리·메모리·GPU 대역폭** | 해상도 스케일 · 프레임 상한 · 텍스처 압축 · 오버드로 |
| PC (스팀 등) | 사양 폭이 넓다 | 옵션 화면 필수 · 해상도/창모드 저장 · 키 리바인딩 |
| 콘솔 | 인증(TRC) · 패드 전용 | 포커스 이동 UI · 안전 영역 · 일시정지 규정 |
| 웹(WebGL) | 단일 스레드 · 초기 로드 용량 | 스레드 API 금지 · 압축 전략 · 첫 로딩 시간 |

**확정표 3행에는 「기기·방향·기준 해상도·최소 사양」 네 값이 전부 있어야 한다.**
「모바일이요」 한 단어는 아무것도 확정하지 않는다.

---

## 입력 — 계층부터 만들고 구현체를 갈아 끼운다

**어떤 플랫폼이든 입력은 인터페이스 뒤에 둔다.** 개발 중엔 키보드로 돌리고
빌드는 터치로 나가는 일이 반드시 생긴다.

```
[예시]
IInputProvider
 ├ Move      : Vector2 (정규화된 이동 입력)
 ├ Look      : Vector2 (조준/카메라)
 ├ Actions   : bool/Pressed/Released (스펙에 정의된 액션 이름으로만)
 └ Pointer   : 화면 좌표 + 눌림 (월드 변환은 View 유틸이 한다)

구현체: KeyboardInput · TouchInput · GamepadInput · ReplayInput(하네스용)
```

- **액션 이름은 스펙에서 온다.** `KeyCode.Space` 를 게임플레이 코드가 직접 읽으면 그 순간 플랫폼이 박힌다
- **`ReplayInput` 을 처음부터 넣는다** — 하네스가 사람 없이 플레이하는 유일한 방법이다
- 입력 개수는 확정표 8행이 정한다. 「조작 2개」로 확정했으면 3번째 조작을 추가할 때
  PD로 돌아온다 (모바일에서 조작 1개 늘리는 것은 화면 설계 전체가 바뀌는 일이다)

### 터치 고유 규약

| 항목 | 규칙 |
|---|---|
| 최소 터치 타깃 | 기준 해상도 px 로 명시. **아이콘 크기가 아니라 히트 영역** |
| 플로팅 조이스틱 | 시작점 = 첫 터치 지점. 화면 어디서 눌러도 잡힌다 |
| 드래그 임계치 | 탭과 드래그를 가르는 px. 안 정하면 탭이 드래그로 먹힌다 |
| 멀티터치 | 허용/금지를 명시. 금지면 두 번째 손가락을 **무시**한다 (마지막 것으로 덮어쓰기 금지) |
| UI 위 터치 | 월드 입력이 UI 를 뚫지 않게 차단. 팝업 뒤 입력 차단은 전면 raycast 이미지로 |

### 패드/키보드 고유 규약

- UI 포커스 이동(상하좌우)이 필요하다 → 화면마다 **첫 포커스 대상**을 정해야 한다
- 「아무 키나」 동작은 리바인딩과 충돌한다. 액션으로만 받는다

## 해상도 · 세이프에리어 — 폭 하나로 맞추면 콘텐츠가 화면 밖으로 나간다

### CanvasScaler 는 프로젝트당 한 번 정하고 바꾸지 않는다

```
[예시] 세로 모바일
UI Scale Mode : Scale With Screen Size
Reference     : 1080 x 1920
Match         : 0 (Width) 또는 대각 보정값 — 확정표에 «값»으로 적는다
```

- **Match 값을 확정표에 적는다.** 화면마다 다르게 두면 같은 UI 가 기기마다 다르게 밀린다
- 폭 기준(Match 0)은 긴 화면에서 위아래가 남고, 높이 기준(Match 1)은 넓은 화면에서 좌우가 잘린다.
  **어느 쪽이 잘려도 되는지**를 기획이 정한다 (배경은 잘려도 되고 버튼은 안 된다)
- 화면비 상한/하한을 정하고 **양 극단에서 스크린샷을 찍는다** (18:9 와 4:3 등)

### 세이프에리어 — 원본에 없어도 우리가 넣는다

```
[예시] 창 구조는 언제나 이 모양
Window (Canvas)
└ SafeArea        ← 여기서만 노치/홈 인디케이터를 피한다
  ├ Content       ← 실제 UI 는 전부 여기 아래
  └ ...
└ Fullscreen      ← 배경·딤·연출은 SafeArea 밖. 화면 끝까지 채워야 한다
```

- **적용 대상과 비대상을 나눈다**: 버튼·텍스트·리스트는 안쪽, 배경·딤·전면 이펙트는 바깥
- 어느 «변»에 적용하나도 정한다 — 세로 모바일은 상·하만, 가로는 좌·우도
- 앵커를 바꾼 뒤 **offset 을 0으로 리셋**해야 한다. 이걸 빼면 기기에서만 어긋난다
- 검사는 «구조»를 센다: SafeArea 노드 밖에 인터랙티브 요소가 있으면 실패

### 화면 방향

- 회전 허용 여부를 확정표에 적는다. 허용하면 **회전 시 재계산이 필요한 것 목록**을 만든다
  (화면 경계 · 세이프에리어 · 조이스틱 원점 · 카메라 가시 영역)
- 회전을 허용하지 않기로 했으면 **빌드 설정에서 실제로 잠근다.** 코드로만 막으면 첫 프레임에 돈다

## 확정표를 «프로젝트 설정»에 반영한다

확정표에 적어 두고 엔진 설정에 반영하지 않으면 **빌드에서만 다르게 나온다.**

| 확정표 행 | 반영할 설정 |
|---|---|
| 3 플랫폼·방향·해상도 | 빌드 타깃 · Orientation · 기본 해상도 · 스플래시 |
| 4 성능 예산 | 프레임 상한(vSync/targetFrameRate) · 품질 레벨 · 텍스처 압축 |
| 2 뷰 | 색공간(Linear/Gamma) · 렌더 파이프라인 · 포스트프로세싱 유무 |
| 12 아트 | 텍스처 최대 크기 · 밉맵 · 오디오 압축 |

- **색공간과 렌더 파이프라인은 초기에 확정한다.** 나중에 바꾸면 전 에셋 재검수다
  ([사고] 3D 시절 색 보정이 2D 스프라이트에서 형체를 지웠다)
- 엔진 설정에는 **딸린 구성요소**가 있다 — 파이프라인 에셋, 품질 레벨별 설정,
  플랫폼별 오버라이드. 짝이 어긋나면 **재생에서만** 터진다
- 저장소에 게임이 여럿이면 **빌드 직전에 그 게임의 설정을 적용**하는 단계를 둔다
- **재생에서만 터지는 것은 정적 검사로 끌어내린다** — 설정 대조 스크립트를 하나 만들어
  확정표 값과 실제 프로젝트 설정을 비교시키고, 다르면 에러로 띄운다

## 성능 예산 — 숫자로 적는다

확정표 4행. **「빠르게」는 예산이 아니다.** 아래를 전부 숫자로 채운다.

```
[예시] 예산표
타깃 기기      : <기종> (최소 사양)
프레임         : 최소 40 FPS / 목표 60 FPS  ← 「평균」이 아니라 «최소»
동시 오브젝트  : 적 300 · 투사체 200 · 이펙트 50
드로우콜       : <N> 이하 (전투 피크 상태)
힙 할당        : 정상 플레이 프레임에서 0 B/frame
로딩           : 첫 진입 <N>초 · 씬 전환 <N>초
메모리         : 상주 <N> MB 이하
발열/배터리    : <N>분 연속 플레이 후 스로틀 없음 (모바일)
```

- **최소 FPS 로 적는다.** 평균 FPS 는 튐(hitch)을 숨긴다. 사람은 평균이 아니라 튐을 느낀다
- 「피크 상태」의 정의를 함께 적는다 — 무엇이 동시에 떠 있을 때인가
- 이 예산이 게이트 G6 의 판정 기준이다. 예산이 없으면 G6 는 통과도 불합격도 못 한다

## 저장 · 생명주기 — 플랫폼이 앱을 언제 죽이는지가 다르다

- **저장 시점**을 정한다: 값이 바뀔 때마다 / 화면 전환 시 / 포커스 잃을 때.
  모바일은 앱이 예고 없이 죽는다 → 포커스 상실(`OnApplicationPause`) 시 저장은 필수
- **저장 스키마에 버전 필드를 처음부터** 넣는다. 마이그레이션 코드는 나중에 써도 되지만
  버전 필드가 없으면 나중에 못 쓴다
- 백그라운드에서 게임 루프가 멈춘다 — **자동 검증엔 `runInBackground` 필수**
- 오프라인 경과 처리가 있으면 **기기 시계 조작**을 전제로 설계한다 (서버 시간이 진실)

## 빌드 · 배포 체크리스트

- [ ] 빌드 타깃·방향·해상도가 확정표와 일치 (설정 대조 스크립트가 통과)
- [ ] 프레임 상한이 예산과 일치 (모바일에서 무제한은 발열이다)
- [ ] 텍스처 압축 포맷이 플랫폼별로 지정됨 (미지정 = 무압축으로 나갈 수 있다)
- [ ] 스플래시·아이콘·앱명이 임시값이 아님
- [ ] 로그·디버그 UI·치트가 릴리즈 빌드에서 꺼짐 (조건부 컴파일로)
- [ ] **실기에서 한 번은 돌렸다.** 에디터 플레이는 플랫폼 검증이 아니다
- [ ] 최소 사양 기기에서 예산표의 최소 FPS 실측

## 함정

| 증상 | 원인 |
|---|---|
| 기기에서만 UI 가 잘림 | 세이프에리어 미적용 · 앵커 변경 후 offset 미리셋 |
| 기기에서만 텍스처가 뭉개짐 | 플랫폼별 압축 포맷 미지정 · 최대 크기 오버라이드 |
| 에디터는 60인데 기기는 20 | 에디터 플레이로 성능을 판정함 (실기 실측이 유일한 판정) |
| 몇 분 뒤부터 프레임이 반토막 | 발열 스로틀. 프레임 상한을 안 걸었다 |
| 앱을 내렸다 올리면 진행이 사라짐 | 포커스 상실 시 저장 없음 |
| 첫 프레임만 가로였다가 세로가 됨 | 방향을 코드로만 잠금 (빌드 설정 미반영) |
| 웹 빌드에서만 멈춤 | 스레드/파일 API 사용 (WebGL 미지원) |
