# PrefabRule — 프리팹 내부 구조 · 조립 단위 · 용량 예산

> [확정표 7] 이 이 문서의 값을 정한다.
> **합격 조건 — 프리팹 하나를 열었을 때 «지금 필요한 것만» 올라온다.** (게이트 G8)

## 프리팹은 «골격»이다 — 완성품이 아니다

프리팹은 「이 화면/오브젝트가 무엇으로 이루어지는가」를 적는 곳이지,
「이 화면이 보여줄 수 있는 모든 것」을 담는 곳이 아니다.

```
✗ 이렇게 자란다                     ✓ 이렇게 유지한다
Window                              Window
├ Tab_Shop      (전체 내용)          ├ TabBar (버튼 6개)
├ Tab_Hero      (전체 내용)          └ Container (빈 노드)
├ Tab_Main      (전체 내용)              ↑ 누른 탭의 Panel 을 여기에 로드
├ Tab_Skill     (전체 내용)
├ Popup_Confirm (미리 넣어 둠)       Popup 은 자기 프리팹으로 따로 산다
└ ...  → 수 MB                       → 수십 KB
```

**용량은 결과일 뿐이고, 진짜 문제는 «수명»이다.** 통짜 프리팹은 안 쓰는 것까지
같은 수명을 갖게 만든다 — 같이 로드되고, 같이 메모리에 남고, 같이 리빌드된다.

---

## 용량 예산 — 숫자로 못 박는다

확정표 7행에 **상한을 적는다.** 없으면 프리팹은 반드시 붓는다.

```
[예시] 예산표
Window 프리팹   : 50 KB 이하
Panel 프리팹    : 30 KB 이하
Component 프리팹: 10 KB 이하
월드 오브젝트   : 20 KB 이하 (아트는 참조로, 프리팹에 박지 않는다)
```

- **검사는 파일 크기로 한다** — 자동화하기 쉽고 거짓말을 안 한다.
  빌드 전 검사 스크립트가 예산 초과 프리팹 목록을 뱉게 한다
- 예산을 넘겼으면 **줄이는 게 아니라 쪼갠다.** 압축이 아니라 분리가 답이다
- 예외를 둘 거면 **사유와 함께 목록에 적는다.** 「이건 어쩔 수 없어서」가 무기록으로 쌓이면 예산이 죽는다

### 용량이 붓는 진짜 원인 넷

| 원인 | 신호 | 처방 |
|---|---|---|
| 안 쓰는 하위 트리를 미리 넣어 둠 | 비활성 노드가 절반 이상 | 별 프리팹으로 분리 + 동적 로드 |
| 반복 요소를 N개 박아 둠 | 같은 이름의 형제 20개 | 1개만 두고 풀에서 복제 |
| 컴포넌트 오버라이드가 쌓임 | 중첩 프리팹의 수정 항목 폭증 | 베리언트로 정리하거나 구조를 다시 |
| 인스펙터에 데이터를 채워 넣음 | 배열 필드에 수십 개 참조 | 데이터로 (`DataFramework.md`) |

## 조립 단위 — 무엇을 프리팹으로 쪼개나

**「따로 살 수 있으면 따로 산다.」** 판단 기준 셋:

1. **다른 수명을 갖는가** — 항상 같이 뜨고 같이 죽으면 한 프리팹, 아니면 분리
2. **다른 곳에서 쓰이는가** — 두 번째 사용처가 생기는 순간 분리
3. **다른 사람이 만지는가** — 아트가 만지는 부분과 로직이 만지는 부분은 분리

```
[예시] 분리 결과
Window          골격 · SafeArea · 상시 노출 요소
Panel           탭/서브 화면 단위
Component       슬롯 · 행 · 카드 · 버튼 세트
Popup           독립 프리팹 (부모 창 안에 넣지 않는다)
Fx              연출 단위 (데이터가 키로 부른다)
```

---

## 계층 — 두 단계까지만

```
Window → Panel → (Component 는 런타임에 붙는다)
```

프리팹 **에셋 안에서** 중첩은 두 단계까지. 세 단계를 넘어가면
- 오버라이드가 어디서 왔는지 못 찾는다
- 하나를 고치면 어디가 깨지는지 모른다
- diff 를 읽을 수 없다

깊이가 필요하면 **중첩이 아니라 런타임 조립**으로 푼다.

---

## Canvas 설정 — 프로젝트당 한 번 정하고 절대 바꾸지 않는다

- **Canvas 는 Window 계층에만 붙인다.** Panel·Component 에 Canvas 를 달면
  드로우콜이 쪼개지고 정렬이 제멋대로가 된다
  - 예외: **자주 바뀌는 작은 영역**을 일부러 별도 캔버스로 분리할 때 (리빌드 격리, `Optimize.md`).
    이건 «성능 사유가 기록된» 의도적 예외여야 한다
- `renderMode` 는 상황마다 다르다 — **프리팹에 저장된 값을 믿지 말고** 창을 여는 코드가 지정한다
- CanvasScaler 설정은 `Platform.md` 가 정한다. 창마다 다르게 두지 않는다
- **픽셀을 환산해 박지 않는다** — 앵커·스트레치로 표현한다. 환산값은 다른 해상도에서 틀어진다

---

## 앵커 패턴 — 네 가지면 대부분 끝난다

| 패턴 | 쓰는 곳 |
|---|---|
| 스트레치(전체) | 배경 · 딤 · SafeArea 컨테이너 |
| 모서리 고정 | 닫기 버튼 · 재화 표시 |
| 변 고정 + 한 축 스트레치 | 상단바 · 하단바 · 리스트 |
| 중앙 고정 | 팝업 본체 |

- **앵커를 바꾼 뒤 offset 을 0으로 리셋한다.** 이 한 줄을 빼서 기기에서만 어긋나는 사고가 반복된다
- 레이아웃 그룹은 편하지만 비용이 있다 — 정적인 배치는 앵커로, 개수가 변하는 것만 레이아웃 그룹

---

## 아트 프리팹에는 스크립트 0개

- 로직은 **로직 프리팹**(코드가 만들고 관리)에만 있고, 아트는 그 자식으로 붙는다
- 이 경계 덕에 프록시 아트 → 에셋 팩 → 자체 제작으로 갈아타도 코드가 안 바뀐다
- 외부 에셋 팩의 데모 스크립트는 **전부 제거 대상**이다
  ([사고] 팩의 데모 스크립트가 키 입력에 자기 Destroy — 풀 오브젝트가 키 하나에 사라졌다)
- **프리팹에 스프라이트/메시를 박지 않는다** (월드 오브젝트) — 데이터가 키로 지정하고
  런타임이 물린다. 박아 두면 아트 교체가 프리팹 재작업이 된다

## 굽는 방식은 확정표 7행이 가른다 — 이 문서가 정하지 않는다

| | 손으로 편집 | 빌더 스크립트로 굽기 |
|---|---|---|
| 맞는 때 | 사람이 에디터를 쓰는 팀 | 자동화가 만들고 사람은 보기만 |
| 장점 | 미리보기 · 미세 조정 | 재현 가능 · 일괄 변경 · diff |
| 대가 | 수백 개 일괄 변경이 지옥 | 룩을 코드로 감 잡기 어려움 |

### 「빌더로 굽기」로 확정했다면

- 빌더는 **덮어쓰기로 GUID 를 유지**한다. 지우고 새로 만들면 Addressable·참조가 전부 끊긴다
- 빌더는 **멱등**이어야 한다 — 두 번 돌려도 결과가 같아야 diff 가 의미를 갖는다
- **YAML 손편집은 금지**한다. 수백 개를 손으로 고치면 반드시 사고 난다.
  구조 변경은 공식 에디터 API 로 (예: Missing Script 일괄 제거)
- 구운 뒤 **스크린샷으로 확인**한다. 「빌더가 에러 없이 끝났다」는 룩의 증거가 아니다

## 검사 — 자동으로 세는 것

```
[예시] 프리팹 감사 스크립트가 뱉는 것
- 예산 초과 프리팹 목록 (경로 · 크기 · 예산)
- 비활성 하위 트리 비율이 높은 프리팹 (통짜 후보)
- Canvas 가 Window 밖에 붙은 프리팹
- 스크립트가 붙은 «아트» 프리팹
- Missing Script 를 가진 프리팹
- SafeArea 밖에 있는 인터랙티브 요소
- 같은 이름 형제가 N개 이상인 노드 (하드코딩된 반복)
```

이 스크립트가 게이트 G8 의 증거물을 만든다. **한 번 만들면 프로젝트 내내 쓴다.**

## 완료 체크리스트

- [ ] 확정표 7행에 조립 단위와 용량 예산이 숫자로 있다
- [ ] 프리팹 감사 스크립트가 있고, 예산 초과 0건이다 (예외는 사유와 함께 목록에)
- [ ] Window 프리팹에 «안 쓰는 탭/팝업»이 들어 있지 않다
- [ ] 반복 요소가 프리팹에 N개 박혀 있지 않다 (1개 + 풀)
- [ ] 중첩이 두 단계 이하다
- [ ] Canvas 가 Window 계층에만 있다 (의도적 분리는 사유 기록)
- [ ] 앵커 변경 뒤 offset 리셋이 돼 있다
- [ ] 아트 프리팹에 스크립트 0개, Missing Script 0개
- [ ] 빌더로 굽는다면 GUID 가 유지되고 멱등이다
- [ ] **실제 스크린샷**으로 룩을 확인했다

## 함정

| 증상 | 원인 |
|---|---|
| 프리팹이 MB 로 붓는다 | 통짜 — 안 쓰는 하위 트리를 미리 넣음 |
| 화면 하나 여는데 오래 걸림 | 위와 같음 + 반복 요소 하드코딩 |
| 프리팹을 다시 구웠더니 참조가 다 끊김 | 지우고 새로 만듦 (GUID 소실) |
| 인스펙터 오버라이드가 어디서 왔는지 모름 | 중첩 3단계 이상 |
| 드로우콜이 이상하게 많음 | Panel/Component 에 Canvas |
| 기기에서만 배치가 어긋남 | 픽셀 환산값 하드코딩 · offset 미리셋 |
| 풀에서 나온 오브젝트가 키 하나에 사라짐 | 에셋 팩 데모 스크립트 잔존 |
| 아트를 교체했더니 코드를 고쳐야 함 | 프리팹에 스프라이트/메시를 직접 박음 |
