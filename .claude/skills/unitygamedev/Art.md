# Art — 에셋 규격 · 반입 · 폴더링 · 씬 · VFX

> [확정표 12] 가 이 역할의 입력이다. 프리팹 «구조»는 `PrefabRule.md`, 화면 규격은 `Platform.md`.

## 이 역할이 지키는 것

아트의 산출물은 **로직이 갈아끼울 수 있는 순수 데이터**다.
아트가 로직을 품는 순간(스크립트 붙은 아트 프리팹) 교체 불가능해지고, 그때부터
아트 교체 = 코드 수정이 된다. 경계를 지키는 것이 아트 역할의 첫 번째 일이다.

## 아트 프리팹에는 스크립트 0개

- 로직은 **로직 프리팹**(코드가 만들고 관리)에만 있고, 아트는 그 자식으로 붙는다
- 이 경계 덕에 프록시 → 에셋 팩 → 자체 제작으로 갈아타도 코드가 안 바뀐다
- 프리팹을 다시 구울 때는 **덮어쓰기로 GUID 를 유지**한다 — 지우고 새로 만들면
  Addressable/참조가 전부 끊긴다

## 아트/UI 는 클라를 기다리지 않는다 — 바인딩 계약만 있으면 된다

기능이 끝나야 프리팹을 만들 수 있는 게 아니다. **바인딩 계약**(노드 이름과 계층 ·
붙을 컴포넌트 · 물릴 필드명 · 경로 상수)만 받으면 아트/UI 트랙은 바로 시작한다
(`PD.md` 트랙 · `UIFramework.md` 바인딩 계약).

- 아트/UI 는 **스크립트 0으로 골격만** 만든다. 컴포넌트는 클라가 마지막에 붙인다
- 그래서 합류가 「연결」로 끝난다 — 이게 트랙이 겹칠 수 있는 유일한 이유다
- **노드 이름과 계층은 계약이다.** 나중에 「정리」하며 바꾸면 바인딩이 전부 끊긴다.
  바꿔야 하면 PD 경유 — 재바인딩까지가 그 작업이다

## 프록시 우선 — 아트가 없다고 개발이 멈추지 않는다

- 슬라이스 단계에서는 절차 생성 프록시(단색 프리미티브·생성 스프라이트)로 전부 대체 가능해야 한다
- 프록시도 **규격은 진짜와 동일**하게 (피벗·스케일·어드레스 키). 그래야 교체가 스왑이 된다
- 프록시 상태로 게이트 G4(루프)를 통과시키고, 아트는 병렬로 진행한다

## 폴더링 — 규칙 하나: 「누가 부르는가」로 나눈다

```
[예시]
_Art/
  Sprites/      원본 이미지 (종류별 하위 폴더)
  Prefabs/
    Fx/         연출 — 데이터가 «키»로 부른다
    Char/       캐릭터 아트 (스크립트 0)
    UI/         UI 아트 조각
  Materials/    머티리얼 «에셋». 런타임 생성 금지
  Fonts/
  Audio/
```

- **머티리얼은 에셋으로 캐싱**하고 런타임 생성 금지. 색 변형은 `MaterialPropertyBlock`
- 셰이더는 프로젝트 네임스페이스 접두어로 이름을 짓는다 (프로젝트 컨벤션 준수)
- 폴더 구조가 곧 **로드 경로**가 되는 경우(Resources) 폴더를 옮기는 것이 코드 변경이 된다 —
  경로 상수를 클래스에 두고 (`UIFramework.md`) 폴더 이동 시 상수만 고친다

## 로드 등록 — 어드레서블이면 «양방향»으로 감사한다

| 방향 | 검사 |
|---|---|
| 데이터 → 등록 | 데이터가 부르는 키 전수가 등록돼 있는가. **미등록은 에러** |
| 등록 → 데이터 | 등록됐는데 아무도 안 부르는 키가 있는가 (빌드에 딸려 가는 쓰레기) |

- 조용한 폴백(흰 구체·빈 스프라이트)으로 덮이면 **한참 못 찾는다.** 없으면 에러로 띄운다
- [사고] 주소 중복 — 옛 에셋과 새 에셋이 같은 키를 물어 어느 쪽이 나올지 몰랐다.
  키 중복 검사를 등록 감사에 포함한다

## 외부 에셋 팩 반입 절차 — 순서 고정

에셋 팩은 데모 프로젝트다. 게임에 그대로 꽂으면 데모의 사정이 게임에 들어온다.

1. **인벤토리**: 확장자별 개수·용량·최상위 구조를 먼저 훑는다
2. **참조 감사**: 팩 안의 스크립트가 실제 에셋(프리팹)에서 참조되는지 GUID 로 센다.
   참조 0인 폴더(데모 씬·레거시 스탠다드에셋)는 통째로 삭제
3. **스크립트 판정**: 참조되는 스크립트도 내용을 읽고 판정한다.
   [사고] 팩의 데모 스크립트가 키 입력에 자기 Destroy — 풀에 들어간 오브젝트가
   플레이 중 키 하나에 사라지는 폭탄이었다. 데모용은 전부 제거 대상
4. **스크립트 제거**: `.cs` 를 지운 뒤 프리팹의 Missing Script 를 **공식 API 로 일괄 제거**
   (YAML 손편집 금지 — 수백 개를 손으로 고치면 반드시 사고 난다)
5. **주소 부여**: 게임이 쓸 것만 등록. 어드레스 키 = 데이터가 부르는 이름
6. **검증**: 위 「양방향 감사」를 돌린다

렌더 파이프라인 호환(빌트인 셰이더 → URP 등)은 반입 직후 확인한다.
마젠타는 눈에 띄지만 **반투명·블렌딩 깨짐은 눈에 잘 안 띈다.**

[사고] 지운 에셋·스크립트의 **잔재가 저장을 막는다** — 삭제 후 씬/프리팹이 저장 안 되면
Missing 참조부터 찾는다.

## 임포트 규격

| 종류 | 규칙 |
|---|---|
| 텍스처 | 플랫폼별 압축 포맷 **명시** · 최대 크기 · UI 는 스프라이트 아틀라스 · Read/Write 끔 |
| 스프라이트 | **PPU 는 캔버스 기준 PPU 와 짝이다** — 하나만 바꾸면 크기가 어긋난다 |
| 모델 | 스케일 팩터 통일(1유닛 기준 명시) · 피벗 = 발밑(캐릭터)/중심(소품) · Read/Write 끔 |
| 애니메이션 | 휴머노이드/제네릭을 프로젝트 단위로 통일 · 클립 압축 · **루프 플래그 확인** |
| 폰트 | CJK 는 TMP **Dynamic** 폰트 에셋 · TTF 우선 · 기본 폰트를 TMP Settings 에 지정 |
| 오디오 | 짧은 SFX = Decompress on load · BGM = Streaming |
| 이펙트 | `maxParticles` 상한 명시 · 그림자 캐스팅 기본 Off |

### 폰트 — 글리프는 «세어서» 확인한다

[사고] 기본 폰트에 한글 글리프가 없어 설명 전부가 두부(□)로 떴다.
**눈으로 보고 「있겠지」 하지 않는다** — 게임이 쓰는 문자 집합을 뽑아 실제 렌더를 스크린샷으로 확인한다.
정적 아틀라스로 CJK 를 구우면 수십 MB 다. Dynamic 이 기본값이다.

## 씬 구성 체크리스트

- [ ] 지면·벽에 콜라이더 ([사고] 렌더러만 있는 지면 — 전원 낙하)
- [ ] 라이트 1개 기준으로 시작, 추가는 성능 실측 후
- [ ] **확정 카메라 각도에서 실제 스크린샷으로** 실루엣·가독 확인 (씬뷰 확인은 확인이 아니다)
- [ ] 대량 오브젝트의 그림자·리플렉션 설정 (수백 개면 그림자만으로 프레임이 죽는다)
- [ ] 색공간(Linear/Gamma)·렌더 파이프라인·포스트프로세싱 유무가 초기에 확정됨
      ([사고] 3D 시절 색 보정이 2D 스프라이트에서 형체를 지웠다)

## 화면·UI 규격

- 기준 해상도·매치 모드·세이프에리어는 `Platform.md` 가 정한다. 아트는 그 규격 «안에서» 그린다
- 터치 타깃 최소 크기를 기준 해상도 px 로 지킨다 (아이콘이 아니라 **히트 영역**)
- 월드 → UI 연출(피해 숫자·HP바)은 **카메라 각도 확정 후에** 붙인다 (`View.md`)
- 정적 아트와 **데이터 종속 아트를 섞지 않는다** — 데이터가 키로 부르는 것은 프리팹에 박지 않는다

## 연출(VFX) 배치 기준

- 연출의 어휘를 **역할로** 나눈다 [예시]: 발사체 꼬리 / 착탄 / 시전 — 데이터가 역할 단위로 참조
- 루프 이펙트(꼬리)와 원샷 이펙트(폭발)는 재생 설정이 다르다 — 풀 재사용 시
  원샷은 Clear 후 재생하지 않으면 두 번째부터 안 보이거나 겹친다
- 화면을 채우는 밀도(동시 이펙트 수)는 **스펙이다.** 기획의 밀도 표를 받아 상한을 지킨다
- 반투명이 겹치면 모바일에서 GPU 대역폭이 먼저 죽는다 (`Optimize.md` 오버드로)

## 산출물은 «눈»이 아니라 «숫자»로 판정한다

만든 사람은 자기가 무엇을 그렸는지 안다. 그래서 **화면에 없는 것도 보인다.**
「그렸다」와 「보인다」는 다른 주장이고, 둘을 같은 것으로 세는 순간 그 뒤가 전부 헛일이 된다.

[사고] 이펙트 24종을 다 그려 놓고 화면에서는 말이 안 되게 나왔다. 그림 문제가 아니라
**재생 문제**였다 — 프리팹이 20fps·1회 재생이라 5프레임이 0.25초에 끝나고,
마지막 프레임에서 얼어붙었는데 그 프레임이 알파 0 이었다.
그림을 24장 더 그려도 화면은 그대로였을 것이다.

### 판정은 «화면에서» 한다

| 이렇게 판정한다 | 이건 판정이 아니다 |
|---|---|
| 실제 플레이 화면을 캡처해 본다 | 스프라이트 시트를 본다 |
| 그 캡처를 확대해 픽셀을 센다 | 「잘 나온 것 같다」 |
| 배경 두 종류(밝은 곳·어두운 곳)에 올려 본다 | 한 배경에서만 확인 |
| 캐릭터 옆에 놓고 상대 크기를 본다 | 혼자 크게 띄워 본다 |

### 셀 수 있는 것 넷 — 인상이 아니라 값이다

이번 프로젝트에서 「어색하다」의 원인은 매번 아래 넷 중 하나였고, **전부 셀 수 있었다.**

| 재는 것 | 세는 법 | 이번에 나온 값 → 증상 |
|---|---|---|
| **외곽선 비중** | 외곽 색 픽셀 ÷ 불투명 픽셀 | 43% → 선이 그림을 잡아먹어 형태가 뭉갬 (25% 이하로) |
| **실루엣 폭의 굴곡** | y 축을 훑으며 구간별 폭 | 30·30·30·20 (평평) → 목·허리가 없어 한 덩어리. 살아 있는 몸은 오르내린다 |
| **접지 그림자** | 아래쪽 반투명 픽셀 수 | **0개** → 탑다운에서 캐릭터가 떠 보임 |
| **명암 단수** | 실제로 쓰인 색 종류 | 2단 → 평면. 레퍼런스 도트는 3~4단 |

`ScreenShot/` 의 레퍼런스와 우리 것을 **같은 방법으로** 재서 표로 놓는다.
표에 「미측정」이 남아 있으면 그 항목은 아직 판정된 것이 아니다.

### 크기는 「정직한 것」과 「눈에 띄는 것」이 다르다

연출 크기를 키우면 눈에 잘 띈다. 그런데 **판정 반경이 있는 연출**은 크기가 곧
「어디까지 맞는가」라서, 부풀리면 사거리를 오인하게 만든다.

- 반경이 **있는** 연출 → 반경 그대로. 하한만 올린다
- 반경이 **없는** 장식 연출 → 키워도 거짓말이 아니다

[사고] 예전에 반경 있는 연출을 2배로 뻥튀기했다가 버그로 잡았다. 같은 실수를 반대 방향으로
반복하지 않으려면 **둘을 코드에서 갈라 둔다.**

## 완료 체크리스트

- [ ] 아트 프리팹에 스크립트 0개, Missing Script 0개
- [ ] 반입 절차 6단계를 순서대로 밟았다
- [ ] 로드 키 양방향 감사 통과 (미등록 0 · 미사용 0 · 중복 0)
- [ ] 텍스처 압축 포맷이 플랫폼별로 지정됨
- [ ] 폰트 글리프를 스크린샷으로 확인함
- [ ] 확정 카메라 각도의 **플레이 스크린샷**이 원장에 있다
- [ ] 프록시 → 실제 아트 교체가 «스왑»으로 끝났다 (코드 수정 0)
