# UIFramework — Window / Panel / Component · 동적 로드 · 풀링

> [확정표 6] 이 이 문서의 값을 정한다.
> **합격 조건 — 화면이 N개로 늘어도 «한 화면을 여는 비용»이 안 커진다.** (게이트 G8)

## 대원칙 — 프리팹은 골격, 내용은 필요할 때 부른다

「무거워 보이는 화면」과 「무거운 프리팹」은 **다른 것**이다.
탭 6개짜리 화면을 만들 때 두 가지 길이 있다:

| ✗ 통짜 | ✓ 골격 + 동적 |
|---|---|
| 탭 6개의 내용물을 전부 프리팹에 넣고 껐다 켠다 | 프리팹에는 **탭 버튼 6개와 빈 컨테이너**만 |
| 프리팹 수 MB. 열 때 전부 로드·인스턴스화 | 프리팹 수십 KB. 누른 탭의 패널만 로드 |
| 안 쓰는 5개가 메모리·리빌드 비용을 문다 | 안 본 탭은 존재하지 않는다 |
| 화면이 늘수록 로딩이 선형으로 늘어난다 | 화면이 늘어도 여는 비용이 같다 |

**「엄청 무거워 보이는 화면인데 프리팹은 KB 단위」가 정상이다.**
프리팹이 MB 로 갔다면 그건 아트가 많은 게 아니라 **구조가 틀린 것**이다 (`PrefabRule.md` 용량 예산).

## 3계층 — Window / Panel / Component

| 계층 | 무엇 | 수명 | 로드 |
|---|---|---|---|
| **Window** | 화면 하나. **Canvas 를 가진 유일한 계층** | 열림~닫힘 | 키로 로드, 닫으면 풀 반납(또는 캔버스만 끔) |
| **Panel** | Window 안의 큰 덩어리 (탭 내용·서브 화면) | 그 탭이 선택된 동안 | **필요할 때 로드**. 안 본 탭은 안 만든다 |
| **Component** | 반복되는 조각 (슬롯·행·아이템 칸·버튼 세트) | 목록이 사는 동안 | **무조건 동적 생성 + 풀링** |

**계층을 넘어 직접 참조하지 않는다.** Window 가 Component 의 내부를 만지면
Component 를 다른 화면에서 못 쓴다.

```
[예시] 계층 그림
Window (Canvas · SafeArea · 탭 버튼 · 빈 컨테이너)
├─ Panel_A   ← 탭 A 를 처음 누를 때 로드
│   └─ Component × N   ← 풀에서 꺼내 채움
└─ Panel_B   ← 아직 안 눌렀으면 «존재하지 않는다»
```

## 키 선언 — 경로는 클래스가 들고 있는다

**경로 문자열을 호출하는 쪽에 흩뿌리지 않는다.** 그 순간 에셋을 옮길 수 없게 된다.

```
[예시] Window
public class <이름>Window : BaseWindow
{
    public static readonly WindowKey<<이름>Window> Key = new (PrefabPath);
    private const string PrefabPath = "UI/<경로>/<이름>Window";
    ...
}

[예시] Component / Panel
public class <이름>Component : BaseComponent
{
    public static PrefabAuto<<이름>Component> PrefabAuto = new (PrefabPath);
    private const string PrefabPath = "UI/<경로>/<이름>Component";
    ...
}
```

- **여는 쪽은 경로를 모른다** — `Key` / `PrefabAuto` 만 쓴다
- 경로 상수는 **한 클래스에 하나**. 같은 경로가 두 곳에 있으면 하나는 반드시 썩는다
- 에셋을 옮기면 상수 한 줄만 고친다. [사고] 하드코딩 경로 + 에셋 이동 → 조용한 null

### 패널이 여럿이고 종류로 갈릴 때 — 팩토리

```
[예시]
enum 종류 → 생성자 딕셔너리 → 경로 조립 → 로더
- 등록은 한 곳(RegisterAll)에서. 새 종류 추가 = 등록 한 줄 + 파일 하나
- 등록 안 된 종류는 «조용히 null» 이 아니라 Assert 로 터뜨린다
```

## 바인딩 계약 — 「연결만 하면 되는」 상태를 만든다

클라가 로직을 만드는 **동안** 아트/UI 가 프리팹을 만들려면(`PD.md` 트랙),
합류 지점이 먼저 선언돼 있어야 한다. 그 선언이 바인딩 계약이다.

```
[예시] 화면 하나의 바인딩 계약 — 트랙을 열기 전에 적는다
화면      : <이름>Window       밴드: Normal
경로 상수 : <이름>Window.PrefabPath = "UI/<경로>/<이름>Window"
노드 계층 : Window > SafeArea > Content > { Title, List, BtnClose }
컴포넌트  : Window 루트에 <이름>Window (Canvas 는 같은 노드)
필드      : TextTitle(TMP) ← Content/Title
            ListRoot(RectTransform) ← Content/List
            BtnClose(Button) ← Content/BtnClose
행 조각   : <이름>RowComponent · IListener { OnClickRow(int index) }
```

| 계약에 들어가는 것 | 왜 |
|---|---|
| **노드 이름과 계층** | 아트가 나중에 «정리»하며 바꾸면 바인딩이 전부 끊긴다 |
| **컴포넌트 이름 + SerializeField 필드명** | 클라가 리팩터로 필드명을 바꾸면 프리팹 참조가 끊긴다 |
| **경로 상수의 소유 클래스** | 두 곳에 같은 경로가 생기는 것을 막는다 |
| **Listener 시그니처** | UI 가 위로 말하는 유일한 통로. 이게 있어야 로직 없이 골격을 만든다 |

- **아트/UI 트랙은 스크립트 0으로 골격만 만든다** (`Art.md`). 컴포넌트는 클라가 마지막에 붙인다
- 계약이 정해진 뒤에는 **노드 이름·필드명 변경이 계약 변경**이다 — 바꾸려면 재바인딩까지가 그 작업
- 코드 생성 방식이라면 계약이 곧 **빌더가 만드는 노드 이름 표**다. 방식이 달라도 계약은 같다

## Window 수명 — 훅은 정해진 것만 쓴다

```
[예시]
Open(listener)      → OpenInternal(...) 이 골격을 돌린다
  └ 상태 Opening → Opening() 훅 → 상태 Opened → 활성화 → 이벤트 발신
Close()
  └ BeforeClosed() → 상태 Closed → OnClose() → 비활성화 → 코루틴 정지 → 이벤트 발신
```

| 훅 | 여기서 하는 일 |
|---|---|
| `Opening()` | 데이터 읽어 UI 채우기. **여기서만 채운다** |
| `OnClose()` | listener 해제 · 구독 해제 · 풀 반납 · **참조 null** |
| `BeforeClosed()` | 닫히기 전 확인(연출 대기·저장) |
| `HandleCanClose()` | 조건부로 닫힘을 막을 때만 (입력 중 등) |

- **`Awake`/`Start` 에서 데이터를 읽지 않는다.** 풀에서 재사용되면 두 번째부터 안 돈다
- **`OnClose` 에서 참조를 전부 끊는다.** 안 끊으면 닫힌 창이 옛 데이터를 물고 있다가
  다시 열릴 때 그걸 보여 준다
- `Close` 와 `ForcedClose` 를 구분한다 — 조건부로 못 닫는 창을 시스템이 강제로 닫아야 할 때가 있다

## 밴드(Band) — 깊이는 «대역»이 먼저, 층이 그다음

`sortingOrder` 를 화면마다 손으로 정하면 **화면이 늘 때마다 충돌한다.**
**대역을 먼저 정하고**, 그 안에서 여는 순서대로 층을 쌓는다.

```
[예시] 밴드 테이블 — 확정표 6행이 이 표를 정한다
밴드          범위        성격                        뒤 화면
Passive        0~ 99      씬 종속 상시 UI (로비 메뉴)  안 끈다
Normal       100~299      대부분의 콘텐츠 창           전체 크기면 뒤를 끈다
LowDepth     300~349      미니 메뉴 · 컨텍스트         안 끈다
Popup        400~599      확인·알림                   안 끈다
Global       600~699      로딩 · 씬 전환              전부 덮는다
Tutorial     700~799      튜토리얼 마스크             입력 통제
Top          800~899      터치 이펙트 · 입력 차단막    -
SystemPopup  900~999      종료 · 치명적 오류          최상위
```

- 새 화면을 만들 때 **먼저 밴드를 고른다.** 숫자를 먼저 고르는 게 아니다
- 밴드 안의 층은 **Management 가 여는 순서대로** 부여한다. 창이 자기 숫자를 정하지 않는다
- 「항상 이 숫자여야 하는 창」은 `ConstantDepth` 같은 예외 표시를 명시적으로 단다
- **전체 크기 창이 열리면 뒤 화면의 Canvas 를 끈다** — 안 끄면 안 보이는 화면이 계속 리빌드된다.
  이게 UI 성능의 가장 큰 단일 항목이다

### 창이 여럿 겹칠 때의 계약

| 상황 | 규약 |
|---|---|
| 다른 창이 위에 열림 | `OnOtherWindowOpened()` 로 알려 준다 (타이머 정지 등) |
| 위 창이 닫혀 다시 보임 | `OnReOpened()` 로 알려 준다 — **여기서 값을 새로 읽는다** |
| 뒤로 가기(백 버튼) | 밴드 우선순위 역순으로 하나만 닫는다. 자동 닫힘 팝업은 대상 제외 |

## Component — 무조건 동적 생성 + 풀링

목록·격자·슬롯을 **프리팹에 미리 N개 박아 두지 않는다.**

```
[예시] 사용
var comp = <이름>Component.PrefabAuto.CreateForUI(container);
comp.Open(this);          // this 가 IListener 를 구현
...
Loader.Restore(comp);     // 목록 갱신·창 닫힘 시 반납
```

- 로더가 **풀에서 꺼내 주고 반납받는다.** `Instantiate`/`Destroy` 를 UI 코드가 직접 부르지 않는다
- 반납 시 **부모·앵커·활성 상태·구독을 리셋**한다 (`Optimize.md` 풀링 3법칙)
- 미리 개수를 아는 목록은 **Preload** 로 프리웜한다 — 첫 열림에서 끊기는 것을 막는다
- **Component 는 자기 부모 Window 의 타입을 모른다.** `IListener` 인터페이스로만 위로 말한다

```
[예시] Listener 규약
public interface IListener { void OnClickSlot(int index); }
private IListener _listener;          // Open 에서 받고 Clear/OnClose 에서 null
```

부모 타입을 직접 참조하는 Component 는 그 화면 전용이 된다. **재사용은 인터페이스에서 나온다.**

## UI 는 «표기»만 한다

- UI 가 게임 규칙을 계산하면, 같은 규칙이 하네스·서버·다른 화면에서 다르게 나온다
- UI 코드에 있어도 되는 것: 값 포맷팅 · 색/아이콘 매핑 · 표시 순서 · 입력을 액션으로 바꾸기
- UI 코드에 있으면 안 되는 것: 데미지 계산 · 확률 추첨 · 해금 판정 · 재화 차감
- 「이 버튼을 누를 수 있나」의 **판정은 시스템**이, **표시는 UI** 가 한다

## 중앙 틱 — 창마다 `Update()` 를 갖지 않는다

```
[예시] 옵트인 인터페이스
IWindowUpdate        : 매 프레임
IWindowUpdatePerSec  : 초당 1회 (남은 시간 표시 등)
IWindowLateUpdate    : 후처리 (월드 추종 등)
```

Management 가 **열린 창만** 돌며 부른다. 닫힌 창은 애초에 목록에 없다.
- 초당 1회로 충분한 것을 매 프레임에 두지 않는다 (타이머 텍스트가 대표 사례)
- 매 프레임 텍스트를 갱신하면 **값이 안 바뀌어도 캔버스가 리빌드된다** — 값 변화 시에만 쓴다

## 구독 — 건 곳에서 푼다

- 시스템 이벤트 구독은 `Opening()`, 해제는 `OnClose()`. 짝이 안 맞으면 닫힌 창이 계속 반응한다
- 풀에서 재사용되는 UI 는 **빼고-다시-걸기(`-=` 후 `+=`)**
- 정적 이벤트는 특히 위험 — 창이 죽어도 델리게이트가 창을 붙잡아 누수가 된다
- **점검법**: `+=` 를 grep 해서 같은 클래스에 `-=` 가 있는지 센다. 없으면 그 자리가 누수다

## 목록 — 세 가지 중 하나를 «고른다»

| 방식 | 맞는 때 |
|---|---|
| 고정 격자 (전부 생성) | 개수가 작고 상한이 있다 (인벤 슬롯 20칸 등) |
| 일반 스크롤 (전부 생성) | 수십 개. 스크롤은 되지만 재활용은 없음 |
| 재활용 스크롤 (뷰 개수만 생성) | 수백~수천. **개수 상한이 없으면 무조건 이것** |

**고정 격자를 스크롤로 착각하지 않는다.** 격자는 재활용도 스크롤도 아니다 —
칸 수가 늘어날 수 있으면 처음부터 재활용 스크롤로 간다. 나중에 바꾸는 것은 재작성이다.

## 확정표 6행의 두 분기

### 로드 방식 — Resources / Addressable

| | Resources | Addressable |
|---|---|---|
| 장점 | 단순 · 동기 로드 | 지연 로드 · 번들 분리 · 패치 |
| 대가 | **전부 빌드에 상주** | 핸들 수명 관리 · 비동기 |
| 규약 | 폴더 규칙만 지키면 끝 | **해제(Release)를 누가 하나**를 정해야 한다 |

Addressable 이면 **주소 등록을 양방향으로 감사**한다 — 데이터가 부르는 키 전수가 등록됐는지,
등록된 키 중 아무도 안 부르는 것이 있는지. 미등록은 **에러**로. 조용한 폴백은 한참 못 찾는다.

### 생성 방식 — 프리팹 편집 / 코드 생성 / 하이브리드

| | 프리팹 편집 | 코드 생성(빌더) | 하이브리드 |
|---|---|---|---|
| 맞는 때 | 사람이 에디터로 다듬는다 | 사람 손 없이 자동화로 굽는다 | 대부분 |
| 장점 | 미세 조정·미리보기 | diff·재현·일괄 변경 | 골격은 코드, 룩은 프리팹 |
| 대가 | 대량 변경이 지옥 | 룩을 코드로 감 잡기 어렵다 | 경계를 명확히 해야 |
| 검증 | **육안(스크린샷) 필수** | 육안 필수 (코드가 맞다는 건 룩이 맞다는 뜻이 아니다) | 동일 |

**어느 쪽이든 육안 검증은 면제되지 않는다.** 배치모드로 컴파일만 돌리고 UI 가 됐다고
보고하는 것은 미측정이다 (`PD.md`).

## 완료 체크리스트

- [ ] 화면마다 밴드가 표에서 골라졌다. 손으로 정한 `sortingOrder` 0건
- [ ] 전체 크기 창이 열릴 때 뒤 화면 Canvas 가 꺼진다
- [ ] 경로 상수가 클래스당 하나, 호출부에 경로 문자열 0건
- [ ] 탭/패널이 **처음 열 때 로드**된다 (열지 않은 탭의 인스턴스 0)
- [ ] 반복 요소가 전부 풀에서 나오고 반납된다 (`Instantiate` 직접 호출 0건)
- [ ] `+=` 와 `-=` 의 짝이 맞는다
- [ ] 창마다 `Update()` 가 없다 (중앙 틱 옵트인)
- [ ] 목록 방식을 «골랐고» 상한 없는 목록이 재활용 스크롤이다
- [ ] SafeArea 노드 밖에 인터랙티브 요소 0건 (`Platform.md`)
- [ ] **실제 플레이 스크린샷**으로 한글·레이아웃·잘림을 확인했다
- [ ] 화면 프리팹 용량이 예산 안이다 (`PrefabRule.md`)

## 함정

| 증상 | 원인 |
|---|---|
| 화면이 늘수록 로딩이 길어짐 | 통짜 프리팹 · 안 쓰는 패널까지 로드 |
