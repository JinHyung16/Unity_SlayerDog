# Optimize — 최적화 기법 · 측정 · 우선순위

> [확정표 4] 가 목표를 정한다. 목표 없는 최적화는 취미다.
> **재기 전에 고치지 않는다. 단, «구조»는 처음부터 넣는다.**

## 두 종류를 섞지 않는다

| | 처음부터 (구조) | 실측 후 (튜닝) |
|---|---|---|
| 왜 | 나중에 넣으면 **갈아엎기**가 된다 | 나중에 넣어도 **덧붙이기**로 끝난다 |
| 예 | 풀링 · 화면 밖 비용 차단 · 핫패스 무할당 · 데이터 주도 · 중앙 틱 | LOD · GPU 인스턴싱 · 잡시스템 · 아틀라스 재구성 · 셰이더 최적화 |
| 판단 | 「이걸 나중에 넣으려면 기존 코드를 얼마나 고치나?」 → 많으면 처음부터 |

**「나중에 최적화하죠」가 정당한 것은 오른쪽 칸뿐이다.** 왼쪽을 미루면
슬라이스가 끝나는 순간 그 슬라이스를 다시 만든다.

## 처음부터 넣는 것 — 넷

### 1. 풀링 — 재사용 객체의 3법칙

대량 오브젝트(투사체·적·이펙트·드랍·피해 숫자)는 풀링이 기본값이다.
풀에 들어가는 모든 컴포넌트는:

1. **반납 시점에 자기 상태를 전부 리셋한다** — 타이머·타깃 참조·배수·플래그
   [사고] 유도 투사체가 이전 런의 타깃 참조를 들고나와 엉뚱한 적을 쫓았다
2. **이벤트 구독은 빼고-다시-걸기(`-=` 후 `+=`)** — 재사용마다 중복 구독이 쌓인다
3. **상태이상·수치 배수는 반납 시점에 원상 복구** — 배수를 곱해놓고 안 풀면 2회차부터 값이 오염된다

- **프리웜을 0으로 두지 않는다.** 플레이 중 Instantiate 가 터지면 프레임이 끊긴다
- **동시 개수 상한**과 상한 도달 시 동작(스폰 중단 / 가장 오래된 것 회수)을 스펙으로 받는다
- 풀은 **키 단위**로 나눈다. 종류가 다른 것을 한 풀에 담으면 리셋 규칙이 섞인다
- 씬 리로드·런 종료 시 풀을 **명시적으로 비운다**. 정적 풀이 이전 런의 인스턴스를 물고 있으면 누수다

### 2. 화면 밖 비용 차단

**엔진 프러스텀 컬링은 렌더러만 끈다.** Update·AI·Animator·파티클은 계속 돈다.

- 개체마다 「나 화면 밖인가?」 컴포넌트를 붙이지 **않는다** — 시스템 하나가 목록을 훑는다
- 프레임당 검사 수를 분할한다 (전체 N개를 K프레임에 나눠 검사)
- **AI 를 완전히 멈추지 않는다** — 멈추면 플레이어에게 접근을 안 한다.
  **틱 간격을 늘리는** 방식으로 (화면 안 = 매 프레임, 화면 밖 = N프레임마다)
- Animator 는 화면 밖에서 꺼도 되는 것과 아닌 것을 구분 (컬링 모드 설정)

### 3. 핫패스 무할당

매 프레임 도는 경로에서 **GC 를 만들지 않는다.** 모바일에서 GC 스파이크는 곧 튐이다.

| 금지 | 대신 |
|---|---|
| `new` (클래스·배열·리스트) | 미리 만든 버퍼 재사용 · 구조체 |
| LINQ | for 루프 |
| 문자열 연결 · `ToString()` | 캐시 · 값이 바뀔 때만 갱신 · StringBuilder |
| `GetComponent` | Awake 에서 캐시 |
| `foreach` (컬렉션 종류에 따라 박싱) | 인덱스 for |
| 람다 클로저 (캡처) | 정적 메서드 · 캐시된 델리게이트 |
| `Camera.main` | 캐시 (내부적으로 Find 다) |

**판정법**: 정상 플레이 상태에서 프레임당 힙 할당이 0 B 인가를 프로파일러로 본다.
0 이 아니면 그 자리를 찾는다. 「조금 나온다」는 없다 — 그 조금이 몇 분 뒤 GC 다.

### 4. 중앙 틱 — Update 를 개체마다 갖지 않는다

수백 개 오브젝트가 각자 `Update()` 를 가지면 엔진이 매니지드↔네이티브 경계를 수백 번 넘는다.

```
[예시]
시스템 하나가 목록을 돌며 대상들의 Tick(dt) 를 부른다.
- 등록/해제는 OnEnable/OnDisable 에서
- 틱 주기가 다른 것은 목록을 나눈다 (매프레임 / 0.1초 / 1초)
- UI 는 열린 화면만 틱한다 (UIFramework.md 의 IWindowUpdate 계열)
```

Manager 마다 `Update()` 를 두는 것도 같은 이유로 피한다 — **순서가 보장되지 않는다.**
게임 루프의 순서가 중요하면 중앙 루프 하나가 정해진 순서로 부른다.

## 실측 후에 하는 것

### 드로우콜 · 배칭

먼저 **무엇이 배칭을 깨는지** 본다. 대개 이 순서다:

1. **머티리얼이 다르다** → 아틀라스로 합치고 머티리얼 수를 줄인다
2. **색만 다른데 머티리얼을 복제했다** → `MaterialPropertyBlock` (런타임 `new Material` 금지)
3. **정렬 때문에 배치가 끊긴다** → 밴드를 재배치해 같은 머티리얼끼리 연속되게
4. UI 캔버스가 통째로 리빌드된다 → **자주 바뀌는 요소를 별도 캔버스로 분리**
   (숫자 하나가 바뀌어 화면 전체 캔버스가 리빌드되는 것이 UI 최다 병목)

### 텍스처 · 메모리

- 아틀라스로 묶되 **같이 뜨는 것끼리** 묶는다. 한 화면 때문에 아틀라스 하나가 통째로 올라온다
- 밉맵: UI 는 끄고 월드는 켠다 (거리 있는 3D). 반대로 하면 메모리와 화질을 둘 다 잃는다
- 최대 크기를 플랫폼별로 지정. **압축 포맷 미지정은 무압축과 같다**
- Read/Write Enabled 는 필요할 때만 (켜면 메모리 2배)

### 오버드로 (모바일에서 특히)

- 전면 딤·반투명 이펙트가 화면을 여러 겹 덮으면 GPU 대역폭이 먼저 죽는다
- 파티클 `maxParticles` 상한을 명시. 화면을 채우는 밀도는 **기획의 스펙**이다
- 안 보이는 UI 는 **비활성**한다. `alpha=0` 은 여전히 그린다 (CanvasGroup alpha 0 도 레이캐스트/리빌드 비용은 남는다)

### 그 다음

LOD · GPU 인스턴싱 · 잡시스템/버스트 · 셰이더 단순화.
**전부 「재 보니 여기가 병목이더라」 다음에** 한다.

## 측정 — 무엇으로 재나

| 재는 것 | 수단 | 주의 |
|---|---|---|
| 프레임 · 스파이크 | 프로파일러 (실기 연결) | **에디터 플레이 수치는 판정이 아니다** |
| 힙 할당 | 프로파일러 GC Alloc 열 | 프레임당 0 B 가 목표 |
| 드로우콜·배치 | 프레임 디버거 · 통계창 | 피크 상태에서 본다 |
| 동시 개수 | 하네스 리포트에 카운터를 찍는다 | 상한 초과 시 무슨 일이 났는지도 |
| 로딩 시간 | 하네스가 스톱워치 | 캐시 상태(첫 실행/재실행)를 구분해 적는다 |
| 메모리 상주 | 메모리 프로파일러 스냅샷 | 씬 전환 전/후 두 장 — 안 줄면 누수다 |

### 실측 규약

- **피크 상태를 재현하는 시나리오를 하네스에 넣는다.** 「대충 플레이하다 보니 느렸다」는 측정이 아니다
- **리팩터 전에 기준값을 확보한다.** 최적화 전후 숫자가 없으면 개선인지 악화인지 모른다
- 한 번에 **한 가지만** 바꾸고 다시 잰다. 세 개를 같이 바꾸면 무엇이 효과였는지 모른다
- 실측 결과는 원장에 **숫자로** 적는다. 「빨라졌다」는 원장에 쓸 문장이 아니다

## 우선순위 — 어디부터 보나

```
1. 튐(hitch)  ← 사람이 제일 먼저 느낀다. 원인은 대개 GC / 로드 / Instantiate
2. 최소 FPS   ← 평균이 아니라 바닥
3. 메모리     ← 넘치면 앱이 죽는다 (모바일)
4. 로딩       ← 이탈률에 직결
5. 평균 FPS   ← 마지막
```

**튐을 놔두고 평균 FPS 를 5 올리는 것은 체감상 개선이 아니다.**

## 함정

| 증상 | 원인 |
|---|---|
| 몇 초마다 규칙적으로 튐 | GC. 핫패스 할당을 찾는다 |
| 적이 늘수록 급격히 느려짐 | 개체별 Update · 화면 밖 비용 미차단 |
| 첫 스폰에서만 끊김 | 프리웜 0 (풀이 비어 Instantiate) |
| UI 숫자만 바뀌는데 프레임이 떨어짐 | 캔버스 통째 리빌드 (동적 요소 분리 필요) |
| 실기에서만 발열 후 반토막 | 프레임 상한 미설정 · 오버드로 |
| 씬을 오갈수록 메모리가 늚 | 풀·정적 이벤트·핸들 미해제 |
| 최적화했는데 체감이 그대로 | 병목이 아닌 곳을 고침 (측정 없이 시작) |
