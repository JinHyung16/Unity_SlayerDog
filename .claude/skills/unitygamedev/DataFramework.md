# DataFramework — SSOT · 굽기 · Registry

> [확정표 5] 가 이 문서의 값을 정한다.
> **합격 조건은 하나다 — 콘텐츠 1개 추가에 C# 수정 0.** (게이트 G7)

## 파이프라인은 세 토막이고, 경계를 넘지 않는다

```
[SSOT]            [굽기]                    [런타임]
사람이 적는 곳  →  검증 + 변환 + 코드생성  →  읽기 전용 Registry
Assets/ 바깥       실패하면 «아무것도» 안 씀    게임 코드는 여기만 본다
```

| 토막 | 규칙 |
|---|---|
| SSOT | **여기만 손으로 고친다.** 굽기 산출물을 손으로 고치면 다음 굽기에 날아간다 |
| 굽기 | **검증 실패 시 산출물을 쓰지 않는다.** 반쯤 갱신된 출력이 제일 나쁘다 |
| 런타임 | **읽기 전용.** 런타임이 데이터를 고치면 그건 세이브지 데이터가 아니다 |

**SSOT 를 `Assets/` 바깥에 둔다.** 안에 두면 `.meta` 가 붙고 빌드에 딸려 가고,
사람이 에디터에서 실수로 고친다.

## 확정표 5행이 정하는 것 — 세 갈래

### ① SSOT 를 어디에 적나

| 선택 | 맞는 때 | 대가 |
|---|---|---|
| **로컬 코드/JSON 트리** | 개발자 1~2명 · 조합형 데이터 · 버전관리 필요 | 비개발자가 못 고친다 |
| **스프레드시트(구글/엑셀)** | 기획자가 따로 있음 · 평면 테이블 | 동기화 절차·인증·오프라인 |
| **ScriptableObject** | 에디터에서 눈으로 보며 튜닝 · 참조 연결이 잦음 | 대량 편집·diff 가 지옥 |

**섞지 않는다.** 두 곳에 진실이 있으면 반드시 어긋난다.
「일단 SO 로 하고 나중에 시트로」는 두 번 만들겠다는 뜻이다 — 처음부터 정한다.

### ② 평면형인가 조합형인가

이게 이 문서에서 제일 중요한 갈림길이다.

| | 평면형 | 조합형(모듈 조립) |
|---|---|---|
| 모양 | 콘텐츠 1개 = 행 1개, 컬럼이 전부 | 콘텐츠 1개 = 모듈 참조 + 슬롯 채우기 |
| 맞는 때 | 축이 적고 서로 독립 (아이템·적 스탯) | 축이 여럿이고 곱으로 늘어난다 (스킬·카드·효과) |
| 콘텐츠 10종 | 행 10개 | 모듈 6개 + 조합 10개 |
| 콘텐츠 100종 | 행 100개 (복붙 지옥) | 모듈 12개 + 조합 100개 |
| 위험 | 같은 값이 수십 행에 복제됨 | 조립 규칙이 복잡해짐 → **빌드 검증이 필수** |

**「종류를 늘리기 전에 축을 늘린다」(`Design.md`)의 데이터 쪽 얼굴이 조합형이다.**
축이 3개 이상이면 조합형이 거의 언제나 맞다.

### ③ 무엇으로 굽나 / 어디로 나가나

- 출력 형식: JSON(가장 무난) · 바이너리(대용량) · ScriptableObject 에셋
- 로드 경로: `Resources` (간단·전부 상주) vs `Addressable` (지연 로드·번들)
- **C# enum 을 같이 생성**한다 — 데이터의 종류 키가 코드에 문자열로 흩어지는 것을 막는다

## 조합형 설계 — 모듈 · 슬롯 · 토큰

조합형을 고른 경우의 규약. (평면형이면 이 절을 건너뛴다)

```
[예시] 트리
GameData/
  _enums.js            enum SSOT ('_' 접두사 = 스캔 제외)
  modules/
    visual/  <이름>    연출 리소스 키 + 색
    stat/    <이름>    수치 + 레벨 곡선
    launch/  <이름>    동작 방식 (형제 노드 목록 + 슬롯)
    buff/    <이름>    idTable — 런타임이 숫자 id 로 조회
  contents/  <id>_<이름>   모듈 조합 + 슬롯 채우기
```

**파일 경로(확장자 제외) = 모듈 ID.** 폴더가 곧 종류다.

### 슬롯 — 모듈이 구멍을 뚫어둔다

모듈은 자기 노드 목록을 내놓고 `{ slot: '이름' }` 으로 구멍을 남긴다.
콘텐츠가 그 자리에 노드를 꽂으면 **빌드 타임에** 교체된다.

- 안 채운 필수 슬롯 → **빌드 실패**
- 모듈이 선언 안 한 슬롯을 채움(오타) → **빌드 실패**
- `optional: true` 슬롯은 안 채워도 통과

### 토큰 — 값은 모듈에서 끌어온다

`@stat.<키>` / `@visual.<키>` 는 콘텐츠가 참조한 모듈 값으로 **빌드 타임에 치환**된다.
**런타임 해석이 전혀 없다.** 없는 키를 쓰면 빌드가 깨진다.

- 모듈을 복제하지 않고 하나만 다르게 하려면 `overrides` 로 그 값만 덮는다
- **런타임 문자열 해석을 만들지 않는다** — 오타가 런타임까지 살아남고, 파싱 비용이 핫패스에 들어온다

### id 참조 — 숫자를 손으로 적지 않는다

`#<종류>/<경로>` 로 쓰면 빌드 타임에 그 모듈의 `id` 로 치환된다.

```
[예시] { type: 'DebuffOnHit', params: { DebuffId: '#debuff/burn' } }   →  DebuffId: 2001
```

**콘텐츠 파일에 숫자 id 를 직접 적지 않는다.** 손으로 적은 id 의 오타는 런타임까지 산다.

## 굽기는 검증이 본체다 — 통과 못 하면 아무것도 안 쓴다

굽기 스크립트가 반드시 잡아야 하는 것:

| 검사 | 안 잡으면 |
|---|---|
| **미구현 원자 사용** | enum 에만 있고 C# 구현이 없는 타입 → 「조용한 무동작」 |
| **죽은 참조** | A 가 없는 B 를 가리킴 → 「등록은 됐는데 안 나온다」 |
| **id 중복** | 뒤엣것이 앞엣것을 덮어씀. 어느 쪽이 이길지 아무도 모른다 |
| **enum 오타** | 문자열 타입 필드의 오타 |
| **필수 필드 누락 / 타입 불일치** | 런타임 파싱에서 조용히 기본값 |
| **구조 규칙 위반** | 조합형의 순서·개수 제약 (예: 종결 노드가 2개, 종결 뒤에 노드가 남음) |
| **bool 열에 숫자** | [사고] `1` 이 조용히 `false` 가 됐다 |

- **검증 실패 = 종료 코드 비0 + 산출물 미갱신.** 경고만 찍고 진행하면 그 경고는 안 읽힌다
- 검증 리포트는 «로드 등급»의 증거물이다 (`PD.md` 측정 등급) — 게이트 G3 가 이걸 본다
- **에디터 쪽 검증기도 따로 둔다** — 굽기를 안 돌리고 에셋만 옮긴 경우를 잡는다

## 런타임 — Registry 하나가 창구다

게임 코드가 **JSON 을 직접 읽지 않는다.** 종류마다 Registry 를 두고 거기만 본다.

```
[예시] 규약
- 로드는 최초 1회 (정적 캐시). 이후 조회는 딕셔너리 히트
- 조회 실패는 «한 번만» 경고하고 null/기본값 (매 프레임 로그 스팸 금지)
- id → 데이터 외에, 자주 쓰는 축은 미리 인덱싱해 둔다 (타입별 목록 등)
- 런타임에 내용을 «수정하지 않는다». 진행 상태는 세이브 쪽에 산다
- 씬 리로드에서 다시 로드하지 않아도 되게 정적으로 두되, 리셋 진입점은 만든다
```

- **Registry 가 곧 화면의 출처다** — 도감·목록 UI 는 Registry 를 그대로 나열하면 된다.
  UI 가 따로 배열을 하드코딩하고 있으면 그 화면은 콘텐츠 추가 때 안 늘어난다
- 하네스가 참조하는 콘텐츠 id 는 **한곳에 모아 둔다**
  ([사고] 시스템을 갈아엎었는데 하네스가 옛 id 를 하드코딩해 게임은 멀쩡한데 0을 보고했다)

## 세이브 — 데이터와 «다른 것»이다

| | 데이터 (이 문서) | 세이브 |
|---|---|---|
| 진실 | SSOT 파일 | 플레이어 기기(또는 서버) |
| 수명 | 빌드에 박힘 | 플레이 중 계속 변함 |
| 버전 | 빌드가 곧 버전 | **버전 필드 + 마이그레이션 필요** |

- 세이브에 **콘텐츠 id 를 저장할 때**는 그 id 가 사라질 수 있음을 전제한다 — 로드 시 죽은 id 를 걸러낸다
- 세이브 스키마에 **버전 필드를 처음부터** 넣는다 (`Platform.md`)
- 데이터 밸런스를 바꿨을 때 기존 세이브가 깨지는지를 **콘텐츠 추가 절차에 체크 항목으로** 넣는다

## 완료 체크리스트

- [ ] SSOT 위치가 한 곳이고 `Assets/` 바깥이다 (또는 이유가 확정표에 있다)
- [ ] 굽기가 **검증 실패 시 산출물을 안 쓴다** (실제로 깨뜨려서 확인했다)
- [ ] enum 이 자동 생성되고, 미구현 원자 차단 목록이 유지된다
- [ ] 죽은 참조·id 중복·타입 불일치를 굽기가 잡는다
- [ ] 게임 코드에 JSON 직접 읽는 곳이 0곳 (Registry 경유)
- [ ] **콘텐츠 1개를 실제로 추가해 봤고 C# 수정이 0이었다** (게이트 G7)
- [ ] 목록형 UI 가 Registry 를 나열한다 (하드코딩 배열 0)
- [ ] 세이브에 버전 필드가 있다

## 함정

| 증상 | 원인 |
|---|---|
| 데이터를 고쳤는데 게임이 그대로 | 굽기를 안 돌림 · 산출물이 갱신 실패했는데 조용히 넘어감 |
| 등록은 됐는데 화면에 안 나옴 | 죽은 참조 · UI 가 하드코딩 배열을 봄 |
| 콘텐츠가 «있는데» 아무 일도 안 함 | enum 에만 추가하고 C# 원자 미구현 |
| 값이 항상 기본값 | bool 열의 숫자 · 컬럼명 오타 · 타입 불일치를 파서가 삼킴 |
| 밸런스를 바꾸니 기존 세이브가 깨짐 | 세이브가 데이터 인덱스를 저장 (id 를 저장해야 한다) |
| 하네스만 0을 보고 | 하네스가 옛 콘텐츠 id 를 하드코딩 |
| 두 사람이 다른 값을 봄 | SSOT 가 둘 (시트와 SO 병행 등) |
