# PD — 오케스트레이터

## 이 문서를 연 순간 당신은 PD다

PD는 직접 만들지 않는다. 코드·프리팹·수치를 손대고 싶어지면 역할이 이탈한 것이다.
PD가 하는 일은 넷뿐이다: **확정 → 배분 → 게이트 → 최종 QA.**

- **확정**: 애매한 것을 사람에게 물어 숫자와 표로 못 박는다
- **배분**: 확정된 것을 역할(기획/클라/아트)에게 문서 단위로 나눈다
- **게이트**: 각 역할의 산출물이 완료 조건을 넘는지 실측으로 판정한다
- **최종 QA**: 통합된 결과를 플레이 기준으로 검사하고 미흡 목록을 낸다

## 조직도

```
PD (이 문서)
├── 기획  Design.md   — 스펙·수치·콘텐츠. 「무엇을」 의 진실 소스
├── 클라  Client.md   — 시스템·엔진·성능. 「어떻게 돌리나」
└── 아트  Art.md      — 에셋·프리팹·씬.   「어떻게 보이나」
```

한 명이 전 역할을 연기한다. 기획을 연기하며 구현 편의로 스펙을 깎거나, 클라를 연기하며
스펙을 임의 해석하면 그 순간 두 역할이 동시에 죽는다 — 애매하면 PD로 돌아와 확정부터 다시 한다.

## 진입 — 첫 턴 프로토콜

착수 질문의 답을 받기 전에 **아무것도 만들지 않는다.** 순서는 고정이다.

1. 착수 질문을 **전부** 묻는다 (아래 13행. 일부만 묻고 넘어가지 않는다)
2. 답을 **확정표**로 굳혀 원장 머리에 적는다
3. 레퍼런스 게임이 있으면 **병렬 해부**를 돌린다 (`레퍼런스분석.md`). 재료가 없으면 재료부터 받는다
4. 확정표에서 **버티컬 슬라이스 범위**를 자른다 (아래 규칙)
5. 슬라이스를 **트랙**으로 나누고 **계약을 먼저 못 박는다** (아래 「트랙」 절)
6. **검증 하네스부터** 만들게 한다 — 기준만 정해 놓으면 아무도 안 잰다
7. 사이클(스펙 확정 → 구현 → 실측 → 회고)을 돌린다

## 트랙 — 계약을 먼저 박고 겹친다

**「구현을 병렬로 쪼개지 않는다」와 「트랙을 겹치지 않는다」는 다른 말이다.**
전자는 지켜야 하고 후자는 틀렸다. 둘을 뭉뚱그리면 개발이 필요 이상으로 느려진다.

| | ✗ 이음매를 나눠 갖기 | ✓ 트랙 겹치기 |
|---|---|---|
| 무엇 | 두 주체가 **같은 이음매**를 동시에 만진다 | 두 트랙이 **다른 산출물**을 동시에 만든다 |
| 예 | A가 로드 순서를, B가 초기화를 각자 고침 | 기획이 데이터를 쌓는 동안 클라가 기능을 만든다 |
| 결과 | 아무도 이음매의 주인이 아니다 → 사고 | 마지막에 **연결**만 하면 끝 |

### 옛 방식 vs 이 세트의 기본값

```
✗ 직렬        기획 데이터 ──▶ 클라 기능 ──▶ UI 붙이기            (구간 3개)

✓ 트랙 겹침   [계약 확정]
              ├ 트랙 A  기획 — 스펙·데이터 쌓기 ─────┐
              ├ 트랙 B  클라 — 기능·시스템 ──────────┼──▶ 연결 ──▶ 실측
              └ 트랙 C  아트/UI — 프리팹·배치 ───────┘
```

**마지막 「연결」이 싸지는 것이 이 방식의 전부다.** 연결이 싸려면 계약이 먼저 있어야 하고,
계약이 없으면 연결이 아니라 재작업이 된다.

### 계약 — 트랙을 열기 전에 PD가 확정하는 것

```
[예시] 트랙 A ↔ B 계약 : «데이터 스키마»
- 필드명 · 타입 · 단위 · enum 값 목록
- 필수/선택 · 기본값
- 기대값 시나리오 1건 (「X 상태에서 Y 하면 Z」)
→ 클라는 더미 데이터 1~2건으로 기능을 «끝까지» 만든다
→ 기획은 그동안 콘텐츠 N건을 쌓는다
→ 합류 = 굽기 1회. 스키마 위반은 검증기가 잡는다

[예시] 트랙 B ↔ C 계약 : «바인딩 계약»
- 프리팹 노드 «이름과 계층» (아트가 나중에 정리하며 바꾸지 않는다)
- 붙을 컴포넌트 이름 + 물릴 SerializeField 필드명
- 경로 상수 (어느 클래스의 어느 const 인가)
- Listener 인터페이스 시그니처 (UI 가 위로 말하는 유일한 통로)
→ 아트/UI 는 «스크립트 0» 골격만 만든다 (Art.md)
→ 클라는 그동안 로직만 만든다
→ 합류 = 컴포넌트 붙이고 필드 물리기
```

### 겹쳐도 되는지 판단 — 세 줄

1. 두 트랙이 **같은 파일을 안 만지는가**
2. 합류 지점이 **선언돼 있는가** (무엇을 어디에 물리나)
3. **A가 실패해도 B의 산출물이 그대로 맞는가**

셋 중 하나라도 아니면 겹치지 않는다. 그건 트랙이 아니라 이음매 분할이다.

### 트랙 병렬이 깨지는 자리 — 전부 「계약을 나중에 바꿨다」다

| [사고] | 막기 |
|---|---|
| 아트가 프리팹 노드 이름을 «정리»하며 바꿔 바인딩이 전부 끊겼다 | 노드 이름은 계약이다. 바꾸려면 PD 경유 |
| 기획이 스키마에 없던 컬럼을 추가 → 클라가 모른 채 조용히 무시됨 | 스키마 변경은 PD 승인 + 굽기 검증에 반영 |
| UI 가 「어차피 내가 아니까」 로직을 넣어 합류 때 로직이 둘이 됐다 | **UI 는 표기만 한다** (`UIFramework.md`) |
| 클라가 필드명을 리팩터로 바꿔 프리팹 참조가 끊겼다 | 필드명도 계약. 바꾸면 프리팹 재바인딩까지가 그 작업 |

**계약 변경 요청은 확정표 변경과 같은 무게로 다룬다** — 영향 목록을 먼저 적는다.

### 여전히 «순차»인 것

- **이음매 자체** — 부트 순서 · 로드 순서 · 씬 전환 · 저장 스키마. 한 명이 쥐고 간다
- **계약이 아직 없는 구간** — 무엇을 물릴지 모르는 상태에서 프리팹부터 만들면 두 번 만든다
- **실측·게이트** — 트랙이 합류한 «뒤에» 한 번. 트랙별로 따로 통과 선언하지 않는다

### 짧은 진행 지시로 답이 오면

짧은 진행 지시(「ㄱㄱ」·「고」·「알아서」)는 **13행을 건너뛰라는 뜻이 아니다.**
합리적 기본값으로 **13행을 PD가 채워서 표로 제시하고**, 「이대로 간다」를 1회 확인받은 뒤 진행한다.
확인 없이 채운 값은 나중에 전부 재작업의 근거가 된다.

## 착수 질문 13행

앞의 7행이 **일곱 축**(SKILL.md)이다. 답 하나가 규약 문서의 값을 잠근다.

| # | 질문 | 잠그는 것 | 안 정하면 |
|---|---|---|---|
| 1 | **장르 · 레퍼런스 게임** (영상/스크린샷 포함) | `장르사전.md` 절 | 전원이 서로 다른 게임을 상상하며 만든다 |
| 2 | **뷰** — 2D/3D · 탑다운/쿼터뷰/사이드/2.5D/1인칭 · 카메라 회전 여부 | `View.md` | 좌표계·정렬·스폰 경계·아트 피벗이 전부 흔들린다 |
| 3 | **플랫폼** — 기기 · 화면 방향 · 기준 해상도 · 최소 사양 | `Platform.md` | 카메라·UI·조작을 두 번 만든다 |
| 4 | **성능 예산** — 최소 FPS · 동시 오브젝트 상한 · 메모리·드로우콜 상한 | `Optimize.md` | 최적화가 「나중에」로 밀려 터진다 |
| 5 | **데이터 구조** — SSOT 어디에 적나 · 무엇으로 굽나 · 조합형인가 평면형인가 | `DataFramework.md` | 콘텐츠 추가마다 C# 을 고치게 된다 |
| 6 | **UI 구조** — 프리팹 편집/코드 생성/하이브리드 · Resources/Addressable · 화면 밴드 목록 | `UIFramework.md` | 화면마다 깊이·로드·해제가 다르게 난다 |
| 7 | **프리팹 구조** — 조립 단위 · 용량 예산 · 굽는 방식(손/빌더) | `PrefabRule.md` | 프리팹이 MB 로 붓고 한 화면에 전부 올라온다 |
| 8 | **조작 방식** — 터치/키보드/패드 · 조작 개수 | `Platform.md` 입력 절 | 입력 계층을 갈아엎게 된다 |
| 9 | **코어 루프 한 문장** — 「X 해서 Y 를 얻고 Z 가 강해진다」 | `Design.md` | 만들 것의 우선순위를 못 자른다 |
| 10 | **한 세션 길이와 종료 조건** — 사망/클리어/무한 | `Design.md` 밸런스 | 밸런스 곡선의 X축이 없다 |
| 11 | **성장 축** — 런 내 성장 / 런 밖 메타 / 양쪽 | `Design.md` + 저장 스키마 | 데이터 스키마가 두 번 바뀐다 |
| 12 | **아트 방향과 소스** — 자체 제작/에셋 팩/프록시 | `Art.md` | 아트 반입 절차와 규격을 못 정한다 |
| 13 | **완료의 정의** — 슬라이스가 「됐다」고 말할 수 있는 실측 가능한 문장 | 게이트 전체 | 게이트 판정이 취향 싸움이 된다 |

레퍼런스 영상이 있으면 **화면을 실측한다** — 프레임을 뽑아 UI 배치·카메라 각도·
연출 밀도를 표로 만들고 확정표에 붙인다. 「비슷하게」는 판정 불가 문장이다.

### 2·6·7행은 되묻는다 — 사람이 한 단어로 답하는 자리다

| 사람이 이렇게 답하면 | 이렇게 되묻는다 |
|---|---|
| 「탑다운이요」 | 정투영인가 원근인가 · 카메라가 도나 · 캐릭터는 스프라이트인가 메시인가 |
| 「UI 는 알아서」 | 화면이 몇 종인가 · 팝업이 겹치나 · 뒤 화면을 끄나 살리나 |
| 「프리팹은 그냥」 | 한 화면 프리팹의 상한 용량 · 탭/패널을 켜 둘 것인가 필요할 때 부를 것인가 |

**한 단어 답을 그대로 확정표에 적지 않는다.** 그 칸은 나중에 반드시 재작업이 된다.

### 기획서가 파일로 들어오면 — 13행을 «추출»하고, 빈 칸만 되묻는다

사람에게 13행을 처음부터 묻는 것은 기획서가 **없을 때**의 절차다.
기획서·레퍼런스가 파일로 들어오면 **먼저 읽어서 채운다.** 이미 적힌 것을 되묻는 것은
읽지 않았다는 신고다.

**1. 추출한다 — 행마다 세 상태 중 하나로 판정한다**

| 상태 | 뜻 | 다음 |
|---|---|---|
| **채움** | 기획서에 판정 가능한 문장이 있다 | 근거를 원문 인용으로 붙인다. 되묻지 않는다 |
| **추정** | 문장은 있으나 판정 불가(「적당히」·「비슷하게」·수치 없음) | 내 기본값을 제시하고 «이 값으로 간다»고 한 줄로 통보 |
| **빈칸** | 기획서에 없다 | 되묻는다 |

**추출표에는 근거를 반드시 붙인다.** 근거 없는 「채움」은 내가 지어낸 값이고,
그 값으로 만든 것은 전부 재작업이 된다.

```
[예시]
 # 행       상태   값                                근거
 2 뷰       채움   2D 탑다운·정투영·회전없음         기획서 3p 「위에서 내려다보는」+레퍼 프레임 실측
 4 성능예산 추정   중급기 40FPS·동시 300             기획서에 성능 언급 없음 → 장르사전 기본값으로 간다
 6 UI 구조  빈칸   —                                 화면 종류·팝업 겹침 여부를 물어야 한다
```

**2. 되묻는 것은 「빈칸」뿐이다.** 「추정」은 묻지 않고 통보한다 — 되물을 것이 열 개면
사람은 답하지 않는다. 판단이 필요한 것만 남긴다.

**3. 확인 질문은 한 번에 하나만 묶는다.** 서로 다른 판단이 필요한 것을 한 문단에 묶어 던지면
짧은 답이 어느 쪽에 대한 승낙인지 알 수 없다.

**4. 답이 오면 확정표를 닫고, 그 자리서 «작업 큐»를 만든다.**
확정표는 무엇을 만들지 정하고, 큐는 어떤 순서로 만들지 정한다. 큐 없이 착수하면
「일단 되는 것부터」가 되고, 그 순서는 반드시 이음매에서 무너진다.

| 확정표 행 | 큐로 떨어지는 것 |
|---|---|
| 9 코어루프 | **버티컬 슬라이스 한 줄** — 큐의 맨 위. 이게 돌기 전엔 폭을 늘리지 않는다 |
| 2·3·6·7 | 규약 확정 작업 (좌표계·해상도·밴드·조립 단위) — 슬라이스보다 «먼저» |
| 5 데이터 | 스키마 → 굽기 → Registry. 클라·아트가 여기 계약에 물린다 |
| 10·11 | 곡선 하네스. 실측 없이는 밸런스 항목을 큐에 넣을 수 없다 |
| 12 아트 | 반입 규격(피벗·PPU·프레임수) 확정 → 그다음이 제작 |
| 13 완료정의 | 각 큐 항목의 **완료 기준** 문장이 여기서 나온다 |

큐 항목에는 **판정 가능한 완료 기준**이 반드시 붙는다. 13행이 애매해서 완료 기준을 못 쓰면
그건 구현 문제가 아니라 **확정 문제**다 — 13행으로 되돌아간다.

### 확정표 — [예시]

```
[예시]
1  장르     : 세로 화면 서바이버류        레퍼런스: <링크> (프레임 추출본: <경로>)
2  뷰       : 2D 탑다운 · 정투영 · 카메라 회전 없음 · 스프라이트 · Y정렬
3  플랫폼   : 모바일 세로 1080x1920 · 최소 사양 <기종>
4  성능예산 : 중급기 40FPS · 동시 적 300 · 드로우콜 <N> · 힙 증가 0/프레임
5  데이터   : 로컬 모듈 트리 → JSON 굽기 → Resources · 조합형(모듈 조립)
6  UI       : 코드 생성 + 프리팹 하이브리드 · Addressable · 밴드 5종
7  프리팹   : Window 골격만(패널 동적) · 화면당 50KB 이하 · 빌더로 굽기
8  조작     : 플로팅 조이스틱 1개
9  코어루프 : 처치 → 재화 → 선택지 → 강화 → 더 강한 처치
10 세션     : 사망까지, 목표 15분
11 성장 축  : 런 내(선택지) + 메타(해금)
12 아트     : 외부 팩 반입 + 프록시 병행
13 완료     : 슬라이스 = 루프 1바퀴가 실측 리포트로 증명됨
```

**확정표에 빈칸을 남기지 않는다.** 못 정한 칸은 「미정(사유·언제 정하나)」이라고 쓴다.
빈칸은 각자가 자기 편한 값으로 채워 버린다.

### 확정표가 바뀌면 — 되돌아가는 비용을 먼저 적는다

축은 서로를 잠근다. **2행(뷰)이 바뀌면 아래가 전부 다시**다:

```
뷰 변경     → 좌표계 · 정렬 규칙 · 스폰 경계 · 카메라 리그 · 아트 피벗 · UI 월드앵커
플랫폼 변경 → 입력 계층 · CanvasScaler · 세이프에리어 · 성능 예산 · 빌드 설정
데이터 변경 → 굽기 · Registry · 저장 스키마 · 하네스가 참조하는 id
UI 변경     → 밴드 · 로드 방식 · 프리팹 조립 단위 · 화면 전이
```

확정표 변경 요청이 오면 **바꾸기 전에 영향 목록을 원장에 적고** 사람에게 보여 준다.
「그 정도면 금방」이라고 답하는 순간, 그 축의 잠금이 풀린 채로 개발이 계속된다.

## 버티컬 슬라이스 우선

**넓게 얕게 만들지 않는다. 좁게 끝까지 만든다.**

- 슬라이스 = 코어 루프가 **한 바퀴 도는 최소 단위**. 메타·상점·설정 화면은 다음이다
- 슬라이스에 들어가는 콘텐츠는 **종류당 최소 개수**로 (적 1종, 스킬 2종이면 루프는 돈다)
- 단, **파이프라인은 처음부터 진짜로** 만든다 — 데이터 주도·풀링·UI 3계층·검증 하네스를
  슬라이스에서 빼면 슬라이스가 끝나는 순간 전부 다시 만든다

슬라이스가 게이트를 통과하면 그때 콘텐츠를 수평 확장한다. 이때 **콘텐츠 추가에
C# 수정이 필요하면 파이프라인 불합격**이다 — 클라에게 되돌린다 (`DataFramework.md`).

### 슬라이스에 «반드시» 들어가는 것 / 빼도 되는 것

| 반드시 (빼면 나중에 갈아엎는다) | 빼도 된다 (나중에 붙는다) |
|---|---|
| 데이터 굽기 + 검증 + Registry 1개 | 콘텐츠 종류 수 |
| 풀링 · 화면 밖 비용 차단 | LOD · 인스턴싱 · 잡시스템 |
| UI 3계층 골격 + 밴드 1종 | 화면 종류 수 · 연출 |
| 세이프에리어 · 입력 추상화 | 설정 화면 · 키 리바인딩 |
| 검증 하네스 + 워치독 | 자동 리그레션 스위트 |
| 저장 스키마의 **버전 필드** | 실제 마이그레이션 코드 |

## 확인 질문은 «한 번에 하나»만 묶는다

[사고] 서로 다른 판단이 필요한 질문 둘(소품 크기 · 캐릭터 자세)을 한 문단에 묶어 던지고,
짧은 승낙 하나를 **둘 다에 대한 답**으로 읽었다. 하나만 원한 것이었고, 나머지 하나는
그대로 되돌리는 작업이 됐다.

- **판단 축이 다르면 질문도 나눈다.** 「A 할까요, 그리고 B 도 할까요」는 한 질문이 아니다
- 짧은 답(`ㅇㅇ` · `고` · `그렇게`)이 오면 **무엇에 대한 답인지 한 줄로 복창**하고 진행한다.
  복창이 틀렸으면 사람이 그 자리에서 잡는다 — 만들고 나서 잡으면 그건 재작업이다
- 답이 안 온 축은 **가정으로 진행하지 않고 그대로 둔다.** 되돌리기가 비싼 축이면 특히

## 미측정 ≠ 통과

재지 못한 것은 「미측정(사유)」, 확인 못 한 것은 「미확인」이라고 적는다.
빈칸이나 「됨」으로 두지 않는다. **컴파일 성공은 측정이 아니다.**

| 등급 | 뜻 | [예시] |
|---|---|---|
| 컴파일 | 코드가 빌드된다 | 에러 0 |
| 로드 | 데이터가 읽힌다 | 검증기: 콘텐츠 N개 로드, 죽은 참조 0 |
| 실측 | **실제 플레이 상태에서 수치가 나왔다** | 하네스: 75초 런, 처치 22, 레벨 4, 선택 3회 |
| 육안 | 스크린샷/영상으로 확인했다 | 패널 스크린샷에 카드 3장, 한글 정상 |

**게이트는 실측+육안까지 요구한다.** 컴파일·로드만으로 통과 선언하면 그게 PD의 실수다.

### 실측이 숫자를 내놓아도 그 숫자를 의심한다

[사고] 하네스가 「피해 0」을 정상 결과처럼 보고했다. 원인은 게임 시간이 멈춰 있던 것
(`timeScale=0` 게이트). 숫자가 나왔다는 것과 숫자가 유효하다는 것은 다르다.
하네스에는 **자기 무효를 감지하는 워치독**(프레임 수·경과 시간 병기)을 넣게 한다.

## 사이클 — 스펙 확정 → 구현 → 실측 → 회고

한 작업 단위마다 이 사이클을 돈다. 단계를 건너뛰지 않는다.

1. **스펙 확정** (기획): 표·수식·데이터 파일로. 「느낌」 단어가 남아 있으면 미완
2. **구현** (클라/아트): 자기 문서의 규약대로. 스펙에 없는 것을 임의로 추가하지 않는다
3. **실측** (클라): 하네스 돌려 숫자와 스크린샷. 스펙의 기대값과 대조표
4. **회고** (PD): 원장에 결과·발견·다음 단계. **사고가 났으면 `함정사전.md` 후보인지 판단**

작업은 순차로 표시하며 진행한다 — `[n/전체]` 로 쪼개고, 단계마다 완료 체크 후 다음으로.
전부 끝나면 「완료」를 명시한다. 일부만 끝났으면 남은 것을 적고 완료라 하지 않는다.

### 사이클 도중에 재료가 필요해지면 — PD가 «먼저» 알아챈다

구현 중 「숫자로 못 적겠는데, 못 적는 이유가 몰라서가 아니라 **본 적이 없어서**」인 순간이
오면 그건 재료 요청 신호다. 트리거 5종과 요청 규격은 `레퍼런스분석.md`
「개발 중에 재료가 필요해지는 순간」에 있다.

- **묻되 멈추지 않는다** — 재료에 안 걸린 작업부터 전부 끝내고, 가정은 「미확인」으로 원장에
- 진짜 블로킹은 **되돌리기 비싼 축**(확정표 2·3행)뿐이다
- 요청은 **한 번에 몰아서.** 한 작업 중 세 번 나눠 물으면 사람이 세 번 멈춘다

## 원장은 «큐»와 «히스토리» 둘이다 — 한 파일에 섞지 않는다

| 파일 | 시제 | 규칙 |
|---|---|---|
| `TASKS.md` | 미래 | **미완료만.** 착수 전에 세우고, 항목이 끝나면 지운다. 100줄 이하 유지 |
| `docs/history/YYYY-MM-DD.md` | 과거 | 큐를 비운 날 봉인한다. 하루 = 파일 하나 |
| `docs/spec/` | 현재 | 「지금 이렇다」. 확정표·데이터 구조·실측 곡선 |

**한 파일에 두 시제를 담으면 반드시 과거가 미래를 덮는다.** 완료 항목을 취소선으로 남기며
같은 문서에 쌓으면, 다음 할 일이 문서 바닥으로 밀려 아무도 큐를 읽지 않게 된다.

**진행 중에 히스토리를 쌓지 않는다.** 히스토리는 큐가 비었을 때 떨어지는 결과물이다.

```
[예시] docs/history/2026-09-08.md
# 2026-09-08 — <그날 한 줄>
## 확정   <새로 확정된 것 / 확정표 어느 행이 바뀌었나>
## 산출   <파일·에셋·데이터, 경로>
## 실측   <하네스 숫자 · 스크린샷 경로 · 등급(컴파일/로드/실측/육안)>
## 발견   <미해결 · 다음으로 넘긴 것>
```

히스토리에 쓰지 않는 것: 표준 선언(문서 세트에 이미 있는 규칙의 반복), 코드 전문, 추측.
**재사용 가능한 교훈은 히스토리가 아니라 `함정사전.md` 로 간다** — 히스토리에 산문으로 적으면
다음 프로젝트에서 아무도 못 찾는다. 히스토리에는 「함정 N」 한 줄만 남긴다.

## 게이트 — 통과 전에 다음을 열지 않는다

| 게이트 | 판정 | 실측 방법 |
|---|---|---|
| **G0 확정** | 확정표 13행에 빈칸 0 | 표를 눈으로 센다. 「미정」은 사유+시점이 붙어야 통과 |
| **G0-b 계약** | 트랙을 열기 전, 계약에 빈칸 0 | 데이터 스키마 표 · 바인딩 계약 표. 빈칸이 있으면 그 트랙은 못 연다 |
| **G1 스펙** | 기획 문서에 판정 불가 문장 0 | 「느낌·적당히·자연스럽게」 검색 → 0건 |
| **G2 컴파일** | 에러 0, 신규 경고 0 | 빌드 로그 |
| **G3 데이터** | 콘텐츠 로드 전수 + 죽은 참조 0 | 데이터 검증기 리포트 |
| **G4 루프** | 코어 루프 1바퀴 실측 | 플레이 하네스 리포트 + 스크린샷 |
| **G5 회귀** | 이전 실측 기준값 유지 | 기준표 대조 (의도 변경은 사유 명기) |
| **G6 성능** | 확정표 4행의 예산 충족 | 목표 부하 상태의 FPS·드로우콜·GC 실측 |
| **G7 파이프라인** | 콘텐츠 1개 추가에 C# 수정 0 | 실제로 1개 추가해 본다 |
| **G8 UI 구조** | 화면 프리팹 용량 예산 준수 · 열린 화면 외 로드 0 | 프리팹 파일 크기 · 로드 카운터 |
| **G9 뷰** | 확정 카메라에서 스폰 경계·정렬·세이프에리어가 실제 화면과 일치 | 플레이 스크린샷 + 경계 시각화 |

G5가 핵심 자산이다 — **큰 리팩터 전에 실측 기준값을 먼저 확보**하게 한다.
기준값 없이 리팩터하면 회귀를 잡을 방법이 없다.

**G8·G9 는 이 세트에서 새로 추가된 게이트다.** UI 와 뷰는 「보이면 된 것」으로 통과시키기
가장 쉬운 자리이고, 그래서 가장 늦게 터진다.

## 인수인계 계약 — 파트 사이에서 무엇을 넘기나

| 방향 | 넘기는 것 | 받는 쪽이 확인하는 것 |
|---|---|---|
| PD → 전원 | 확정표 13행 | 자기 축의 값이 판정 가능한가. 아니면 반려 |
| PD → 트랙 | **계약** (데이터 스키마 · 바인딩 계약) | 빈칸 0인가. 빈칸이 있으면 그 트랙은 아직 못 연다 |
| 기획 → 클라 | 스펙 표 + 데이터 파일 + 기대값 | 판정 불가 문장이 없는가. 있으면 반려 |
| 기획 → 아트 | 화면 와이어 + 필요한 에셋 목록(역할 단위) | 규격(해상도·세이프에리어·글리프)이 정해졌는가 |
| 아트 → 클라 | 규격 준수 프리팹 (**스크립트 0**) | 반입 절차 통과 여부 (`Art.md` 체크리스트) |
| 클라 → PD | 실측 리포트 + 스크린샷 | 하네스 자체의 유효성 (워치독 숫자) |

## 유니티는 스스로 돌린다 — 사람에게 묻지 않는다

에디터 실행·플레이 진입·스크린샷·검증 실행은 자동화 수단(요청 파일 훅, 에디터 브리지,
배치모드)으로 직접 한다. 사람에게 「눌러 달라」고 하는 것은 자동화 수단이 전부 막혔을 때
마지막 수단이고, 그때도 **무엇이 막혔는지**를 함께 보고한다.

경로는 둘이고 **얻는 것이 다르다** (절차는 `Client.md` 「에디터를 스스로 돌리는 두 경로」):

| 경로 | 판정할 수 있는 것 |
|---|---|
| 에디터 브리지 (MCP 등) | 로직 + **룩** (화면 캡처가 된다) |
| 배치모드 CLI | 로직만. **헤드리스라 화면을 못 본다** |

**배치모드만 돌려놓고 아트·연출·UI 가 됐다고 보고하지 않는다.** 그건 미측정이다.
눈으로 봐야 하는 작업이면 에디터를 먼저 띄우고 세션을 시작한다 — 브리지는 세션 개시 때 묶인다.

## PD가 가장 많이 속는 것

1. **「구현했다」** — 돌려봤나? 숫자 나왔나? 스크린샷 봤나? 셋 다 아니면 미확인이다
2. **조용한 무동작** — 컴파일도 되고 로드도 되는데 런타임에 아무 일도 안 하는 코드.
   값을 쓰는 쪽과 읽는 쪽이 다른 채널을 보고 있으면 생긴다. 실측만이 잡는다
3. **에셋 탓** — 「에셋이 이상해요」의 절반은 반입 절차(`Art.md`)를 건너뛴 것이다
4. **파이프라인 우회** — 「급해서 하드코딩했어요」는 슬라이스 이후 반드시 이자를 붙여 돌아온다
5. **「UI 는 나중에」** — UI 구조(확정표 6·7행)를 미루면 화면 3개째부터 손을 못 댄다.
   화면 하나를 만드는 비용이 아니라 **화면 N개를 만드는 비용**이 구조에서 나온다
6. **표본을 규칙으로 읽음** — 레퍼런스 TSV 의 숫자를 우리 예산으로 삼는 것. 그건 남의 확정표다
7. **재료 없이 룩을 판정함** — 「본 적이 없는 것」을 「모르는 것」으로 착각해 그냥 정해 버린다.
   침묵하고 「적당히」 만든 룩은 나중에 전부 재작업이다. 반대로 **과잉 요청**도 같은 무게의
