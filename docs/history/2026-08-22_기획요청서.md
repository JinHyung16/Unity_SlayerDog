# 기획 요청서 — 뱀서류 (2026-08-22)

클라 쪽에서 할 수 있는 건 다 끝냈다. 아래 3개 표를 채워주면 그대로 DB(`_DataExporter/GameData`)에 찍고 돌린다.
**수치 없는 문장(「강해진다」「적당히」)은 반려한다** — 판정 가능한 숫자로.
빈 칸은 「기본값 써라」로 읽는다. 기본값은 각 표 아래에 적어뒀다.

## 표 1. 캐릭터 컨셉 + 시작 스킬

3D 스틱맨 모델은 공통이고 **컨셉·스탯·시작 스킬만** 다르다. 최소 3명.

| 캐릭터 ID | 이름 | 컨셉 한 줄 | 시작 스킬 ID | 기본 HP | 이속 | 고유 패시브(수치) | 해금 조건 | 색(틴트) |
|---|---|---|---|---|---|---|---|---|
| 2001 | | | | | | | 기본 | |
| 2002 | | | | | | | | |
| 2003 | | | | | | | | |

- 기본값: HP 100, 이속 5.0, 시작 스킬 1개, 패시브 없음
- 「고유 패시브」는 아래 증강 표의 종류 중 하나로 적으면 바로 된다 (예: `AttackSpeedBoost 0.1`). 새 종류면 종류 이름과 수치 규칙을 같이.
- 해금 조건은 「누적 킬 N」「N분 생존」「보스 처치」 중 택 — 그 밖의 조건은 시스템이 없다.

## 표 2. 스킬 목록 (12개 검토 + 추가)

현재 12개는 [로비 스킬 탭]에서 설명이 보인다. **바꿀 것만** 적어도 된다. 추가는 새 행.

| 스킬 ID | 이름 | 발동 | 타겟팅 | 수치 (Lv1) | 성장축 (Lv당) | 최대 Lv | 속성 | 상태이상 |
|---|---|---|---|---|---|---|---|---|
| 1001 | Ember Shot | 공격 때마다 | 가장 가까운 적 | 피해 ? / 탄속 ? | 피해 +? | ? | 화염 | 화상 ?/s × ?s |
| ... | | | | | | | | |

- 발동: `OnAttack`(공격마다) / `OnTick`(쿨타임 N초) 두 가지. 쿨타임이면 초를 적는다.
- 타겟팅: 가장 가까운 / 가장 먼 / 무작위 / 전방 / 자신 / 주변 원형(반경).
- 성장축은 **한 축만** (피해·개수·반경·쿨타임 중 하나). 두 축이면 두 스킬로 나눈다.
- 속성은 화염·냉기·번개·독·신성·물리 중. 표 3의 「속성 증강」 묶음 단위가 된다.
- 상태이상은 화상(DoT)·둔화(이속 %)·기절(초)·독(DoT) 중. 중첩 규칙(갱신/중첩 N/무시)도 적는다.

## 표 3. 증강 (핵심 — 이게 안 오면 게임이 안 늘어난다)

레벨업 3택1. **종류 × 수치 × 등장조건 × 중복 × 가중치** 다섯 칸이 다 차야 한 행이다.

| 증강 ID | 이름 | 종류 | 대상 | 수치 | 등장 조건 | 중복 허용 | 최대 중첩 | 가중치 | 설명(수치 포함) |
|---|---|---|---|---|---|---|---|---|---|
| 4001 | Power | StatBuff | 전체 | 공격력 +20% | 없음 | O | 5 | 10 | 공격력 +20% |
| 4020 | Chain Mastery | StatBuff | 전체 | 공격력 +15% | 1004 보유 | O | 3 | 8 | [번개] 보유 시 공격력 +15% |
| 4010 | Frost Lance | GrantSkill | 1003 | — | 미보유 | X | 1 | 6 | 얼음창 획득 |
| 4100 | | SkillMod | 1004 | 쿨타임 −20% | 1004 보유 | O | 3 | | 번개 쿨타임 −20% |
| 4101 | | SkillMod | 1001 | 투사체 +1 | 1001 보유 | O | 2 | | 불씨 +1발 |
| 4200 | | ElementBuff | 화염 | 피해 +25% | 화염 스킬 1개↑ | O | 3 | | 화염 피해 +25% |
| 4300 | | Evolve | 1001→? | | 1001 Lv Max + 4200 보유 | X | 1 | | |

- **종류**는 5개로 고정 제안: `StatBuff`(전체 스탯) / `GrantSkill`(스킬 획득) / `SkillMod`(특정 스킬 수치) / `ElementBuff`(속성 묶음) / `Evolve`(진화). 이 중 **SkillMod·ElementBuff·Evolve 는 아직 데이터 구조가 없다** — 표가 오면 구조를 만든다. 수치 칸은 「어느 값을 얼마나」(쿨타임 −20% / 투사체 +1 / 반경 +1u) 로.
- 등장 조건: 「없음 / 스킬 N 보유 / 스킬 N 미보유 / 속성 X 스킬 K개 이상 / 증강 M 보유 / Lv N 이상」 조합. 다른 조건은 없다.
- 풀이 3개 미만일 때 동작도 정해달라: (a) 있는 만큼만 (b) 「체력 회복 20%」 같은 채움용 고정 증강.
- 가중치는 상대값. 등급(일반/희귀/전설)으로 묶어 가중치 3개만 정해도 된다 — 그럼 등급 칸을 하나 추가한다.
- 같은 것을 다시 집었을 때: 중첩이면 수치가 **합산인지 곱연산인지** 한 줄.

## 클라에서 알아둘 것 (기획 판단에 영향)

- **사망 조건**: 현재 플레이어는 재시작만 있다. 부활(광고/재화)이 있으면 상점 표와 같이.
- **이펙트 스케일**: 팩 VFX 일부가 화면을 덮는다. 아트 규격(스킬당 최대 반경 u)을 정하면 그 값으로 한 번에 맞춘다.
- **해금 → 증강** 파이프: 스킬 해금(로비 스킬 탭)은 표 2의 「해금 조건」 칸이 오면 켠다. 지금은 12개 전부 해금 상태.
- 표를 주면 순서는 **표 3 → 표 1 → 표 2 → 표 4** 로 반영한다. 증강이 제일 많이 플레이를 바꾼다.
