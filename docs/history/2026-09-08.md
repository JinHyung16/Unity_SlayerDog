## 산출
### UI 프레임워크 계약
- Window: `await UIManagement.OpenAsync(Key)` 로 세우고 호출자가 `Open()`.
  **Awake · OnEnable 에 논리를 두지 않는다 — 열 때 채우고 닫을 때 비운다**
- Panel: `Open(window)` / `Show` / `Hide` / `Close`. 탭이 처음 눌릴 때 `PrefabAuto.CreateForUI` 로 게으르게 생성
- Component: `PrefabAuto<T>` 로 꺼내고 `UILoader.Restore` 로 풀에 반환. `Clear()` 가 값·리스너를 지운다
- Management 는 씬 수명 — 깊이 배정 · 전체 화면 창 아래 Canvas 끄기 · 중앙 틱 · 닫힌 창 파괴 · `UILoader.ClearAll`
- 첫 화면도 예외 없이 키로 연다: `GameFlow.Bootstrap → OpenLobby`
- 파일: `UI/Runtime/Framework/` 13 · `UI/Runtime/Lobby/` 9 · `UI/Editor/UIPrefabBuilder.cs`
- **프리팹은 손으로 만들지 않는다** — `editor.task ui` 가 9개를 굽고 SerializeField 를 SerializedObject 로 묶는다.
  같은 경로에 덮어써 GUID 가 유지된다

### 이동키 설정
`InputBindings` 는 ScriptableObject 다. 런타임에 직접 고치면 **에디터에서는 에셋이 영구 오염되고
빌드에서는 껐다 켜면 사라진다** — 같은 코드가 두 환경에서 정반대로 동작한다.
「기본 배치」는 에셋에, 「사용자가 고른 것」은 `InputSettings`(PlayerPrefs) 에.
- 프리셋 2종(WASD · 방향키)만. 임의 리바인딩은 중복 키 검사를 빠뜨리면 「움직일 수 없는 저장」을 만든다
- 설정 탭에서 해상도와 같은 `IListener` 를 쓰므로 index 를 100 부터 뗀다 — 안 떼면 해상도를 눌렀는데 이동키가 바뀐다

### 성좌 편집기
**모델은 하나다 — 방향 없는 그래프.** 노드를 놓고 잇는 것이 전부이고 그 간선이 곧 「살 수 있는 순서」다.

```
생성기(시드)  →  편집기  →  중간 형식 JSON        →  export.js  →  Resources
「초안 굽기」    손보기      GameData/_raw/*.json     「굽기」      (있으면 시드보다 우선)
```

| 입력 | 하는 일 |
|---|---|
| 좌클릭 | 고르기 · 끌기 (손 뗄 때 격자 정렬) |
| Shift+클릭 두 번 | 잇는다 / 이미 이어져 있으면 끊는다 |
| Ctrl+클릭 | 고른 노드에 이어진 새 노드 |
| Del | 지운다 (코어는 못 지운다) |
| 가운데 버튼 | 화면 이동 — 좌클릭에 두면 나중에 범위 선택 자리가 없다 |

`ConstellationValidator` 는 **첫 오류에서 멈추지 않고 전부 모아서** 보고한다.
하나 고치고 다시 돌리기를 반복하게 만들면 검증을 아예 안 누르게 된다.

### UI 스프라이트 통일
화면이 전부 단색 사각형이었다 — 모서리도 테두리도 없어 카드인지 배경인지가 색 하나로만 갈렸다.

| 스프라이트 | 크기 | 쓰는 곳 |
|---|---|---|
| `ui_rectangle_small_01` + `_frame_` | 128² | 버튼 · 탭 · 카드 · 파츠 줄 |
| `ui_rectangle_big_02` + `_frame_` | 256² | 내비 레일 · 성좌 창 · 정보줄 |
| `ui_circle_bg_small_01` | 128² | 성좌의 별 |
| `ui_slider_bg_small_01` | 128² | 체력 · 경험치 막대 |

- 쓰는 7장만 `Resources/UI/`. **Resources 는 참조가 없어도 빌드에 통째로 들어간다** —
  「나중에 쓸지도」를 거기 두면 용량이 조용히 는다
- Resources 를 쓴 이유는 **굽는 쪽과 도는 쪽이 같은 길을 써야 하기 때문**이다.
  둘이 AssetDatabase / Addressable 로 갈리면 「에디터에선 보이는데 빌드에선 없다」가 난다
- 계층: `UISkin`(어떤 그림) · `UIBuild`(무슨 색·얼마나 둥글게) · 빌더/HUD(어디에)

## 발견
- **`spriteBorder` 를 `pixelsPerUnitMultiplier` 6~12배로 가렸었다.** 화면은 그럴듯해 보이지만
  모서리 아트를 1/8 로 우겨넣는 것이라 곡률이 뭉개진다 (함정 50)
- **경계 두께는 코드에 적지 않고 스프라이트에서 읽는다**(`sprite.border`). 적어 두면 임포트 설정을 고쳤을 때
  조용히 어긋나고 「모서리가 좀 이상한데」로만 보여 원인을 못 찾는다
- **meta 를 고쳤다고 반영된 것이 아니다.** 리임포트가 돌아야 한다 — 굽을 때마다 실제 값을 로그에 찍는다
- **원은 9슬라이스로 붙이면 안 된다.** 가운데가 늘어나 캡슐이 된다
- **테두리를 레이아웃 그룹 안에 얹었더니 칸을 하나 차지했다.** 테두리는 부모를 덮는 장식이지 목록의 한 칸이 아니다
- 모서리는 크기에 비례해야 같아 보인다. 100px 카드에 버튼과 같은 10px 를 주면 각져 보인다
- 여백 0 이던 카드 목록이 화면 오른쪽에서 잘렸다 — **단색이던 시절엔 안 보이던 것이 모양이 생기니 보이기 시작했다**
- 노드를 만드는 자리가 넷인데 **두 곳만 자리 검사를 했다.** 같은 판정은 한 함수에 모으고 전 경로가 거치게 한다 (함정 47)
- 길이 0 인 길에서 비켜세우기가 방향을 못 구해 그냥 빠져나갔다 — **방향이 없는 것과 비킬 필요가 없는 것은 다르다** (함정 48)
- 배율을 상수로 박으니 갈래가 창 밖으로 잘렸다. 창 크기와 **경계 상자**에서 계산한다 (반경으로 맞추면 눌린 성좌에서 가로가 남는다)
- 16:9 라 성좌를 세로로 눌렀다(0.62). 위·아래 갈래는 그 눌림을 그대로 받으므로 **데이터에서** 부채꼴 폭을 76 으로 키웠다
- **왕복 검사를 자동화에 넣었다.** 편집기는 사람이 클릭해야 도는데 저장 형식이 깨진 것은 「다음에 열 때」 알게 된다 —
  그때는 이미 한나절 작업이 사라진 뒤다. 형식은 클릭 없이 잰다
- 이름·설명을 저장에 적지 않는다. 특성에서 나오는 값이라 두 곳에 두면 값 조정 때마다 이름이 조용히 거짓말이 된다
- 그리기와 클릭이 **같은 상자**를 쓴다(`NodeBox`). 다른 도형이면 「보이는데 안 잡히는」 버그가 난다
- `DeathFlowCheck` 의 요청 감시가 「플레이 중이 아닐 때만」 걸려 있었다 — **감시는 항상 걸고,
  빠지는 판단은 감시자 안에서 한다** (함정 49)
- `EnemySpawner` 예열이 프리팹 캐시보다 먼저 돌아 매 부팅 에러 1건 → `IsPrefabReady` 가드
- `DeathFlowCheck` 가 5회 연속 「60초 안에 사망하지 않음」이라 뒤 단계가 한 번도 실측되지 못했다 → 8초 뒤 강제 사망
- Editor.log 는 늦게 비워져 「이 런의 에러」를 가려낼 수 없다 — 하네스가 `logMessageReceived` 로 직접 센다
- `running.ps1` 이 AssetImportWorker 까지 세어 「인스턴스 5개」로 거부했다. **자식 프로세스는 인스턴스가 아니다**
