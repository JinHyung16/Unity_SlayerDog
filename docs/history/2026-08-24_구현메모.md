# 개많이잡아 — 파츠/스킬 구현 메모

기획서(노션)에서 뺀 **개발 쪽 매핑**만 모아둔 문서.
기획 수치·설명의 원본은 노션이 SSOT. 여기는 「그걸 엔진으로 어떻게 만드나」만 적는다.

## 구조 전환 요약 (뱀서류 → 파밍 로그라이크)

| 기존 | 새 구조 | 코드 영향 |
|---|---|---|
| 레벨업 3택1 증강 | **파츠 착용** (필드 드랍) | 증강 선택 UI 폐기, 인벤/장착 신규 |
| 증강 = 전역 or 스킬 한정 버프 | **파츠 옵션** (그 파츠의 스킬만 강화) | `ModifySkill` 필요 — 아래 1순위 |
| 스킬 슬롯 4 | **부위 6칸** (입·발·꼬리·머리·목·등) | 슬롯 키를 부위 enum 으로 |
| 무한 평면 스폰 | 200×200 맵 + 배회 + 파밍 포인트 | 맵·스폰 전면 교체 |
| 3D 퍼스펙티브 | **2D 스프라이트 · 오쏘그래픽** | 아래 「2D 전환」 참고 |
| 레벨업 = 선택 | 레벨업 = 자동 스탯 상승 | 선택 흐름 제거 |

**스킬 로직 자체(BT 노드·발사·타격)는 그대로 쓴다.** 바뀌는 건 「무엇이 스킬을 켜는가」뿐이다.

## 2D 전환 — 실제 비용

- **충돌은 이미 XZ 평면 2D다** (원 vs OBB 자작, `Assets/Scripts/Collision`). 게임플레이 로직 변경 거의 없음
- 카메라만 오쏘그래픽으로. `CameraFollow.cs` 의 `fieldOfView` 경로가 유일한 퍼스펙티브 의존
- 실제 비용은 **아트 전량 재제작**. 다만 기존 Free Stickman 은 임시라 어차피 새로 만들어야 했다
- 파츠 장착 표현은 3D 어태치먼트보다 **2D 스프라이트 레이어링이 훨씬 싸다** — 파츠 시스템과 궁합이 좋다
- 필수 규격: 몸통 스프라이트의 **부위별 피벗 좌표 6종**. 이게 없으면 파츠가 몸에 안 붙는다. 아트 착수 전 확정

## 데이터 id 규칙

| 대상 | id 대역 |
|---|---|
| 공용 파츠(스킬) | 2001 ~ 2024 |
| 캐릭터 고유 파츠 | 2101 ~ |
| 파츠 옵션 | `4000 + (파츠id - 2000) * 10 + 특성번호` |

특성번호: 1 피해 · 2 쿨타임 · 3 치명타확률 · 4 치명타피해 · 5 범위 · 6 개수 · 7 지속시간 · 8 고유

옵션 100여 개를 손기입하지 않는다. 노션 파츠별 목록을 입력으로 익스포터가 생성한다.

## 부위 배치 (부위당 4종)

| 부위 | 파츠 |
|---|---|
| 입 | 개튼튼 치아 · 왈왈 · 으르렁 · 하품 |
| 발 | 뒹굴기 · 발톱 세례 · 우다다 모드 · 뼈다귀 매설 |
| 꼬리 | 꼬리 흔들기 · 정전기 털 · 꼬리 채찍(신규) · 꼬리 프로펠러(신규) |
| 머리 | 개눈빛 레이저 · 냄새 추적 · 귀 쫑긋(신규) · 제3의 눈(신규) |
| 목 | 무리 울음 · 개쌘놈 모드 · 털뭉치 보호막 · 사료 유성우 |
| 등 | God-사료 폭탄 · 원반 물어오기 · 테니스공 물어와 · 슬리퍼 투척 |

고유 파츠는 해당 부위를 **잠근다** — 시바=목, 코기=꼬리, 그레이하운드=발.
장착 로직에서 「고유 파츠가 점유한 부위는 교체 불가」 플래그가 필요하다.

## 신규 파츠 4종 → 엔진 노드 매핑

| name | 노드 트리 |
|---|---|
| tail_whip (꼬리 채찍) | TargetNearestBackward(신규) → LaunchStraight → DespawnAfterHits(2) → HitSingle |
| tail_copter (꼬리 프로펠러) | TargetSelf → BuffSelf(MoveSpeedBoost) + DespawnAfterTime(3) → HitArea(Interval 0.4) |
| ear_sonar (귀 쫑긋) | TargetSelf → LaunchInstant → HitArea(Radius 4) + DebuffOnHit(Reveal 신규) |
| third_eye (제3의 눈) | TargetHighestHp(신규) → LaunchStraight → HitSingle(관통) |

## 파츠의 두 가지 레벨 개념 (혼동 주의)

| | 무엇 | 저장 | 엔진 |
|---|---|---|---|
| 파츠 카드 레벨 | 아웃게임 영구. 그 파츠의 **런 시작 수치**를 올린다 | 세이브 (유저 귀속) | 신규 — 레벨 → 기본 파라미터 배율 |
| 파츠 옵션 | 런 한정. 주운 개체에 붙어 있다 | 런 종료 시 폐기 | `ModifySkill` (신규) |

수치 적용 순서 고정: `기본값 × 카드레벨 배율 → 파츠 옵션`. 반대로 하면 곱연산 결과가 달라진다.

파츠 카드 레벨: 최대 Lv15, `기본값 × (1 + 0.08 × (Lv-1))` → Lv15 = 2.12배. 비용 `100 × Lv²` 사료.

## 엔진 미구현 (착수 전 처리 필요)

**1순위 — 이게 없으면 파츠 시스템 자체가 성립 안 함**
- **`ModifySkill`** — 특정 스킬 인스턴스의 파라미터(피해·쿨·범위·개수·치확·치피·지속)를 수정.
  현 엔진 증강은 전역 `StatBuff` + `requiresSkillId` 등장 게이트뿐이라 「이 파츠의 스킬만 피해 +30%」를 못 한다
- **파츠 인스턴스 개념** — 같은 파츠라도 개체마다 옵션이 다르다. 스킬 데이터(원형)와 런타임 인스턴스(옵션 포함)를 분리해야 한다
- **부위 슬롯 6칸 + 장착/교체** — 현재는 시작 스킬 목록만 있고 런 중 교체 개념이 없다

**2순위 — 파밍 루프**
- 파밍 포인트 5종 (택배 상자 · 밥그릇 · 개집 작업대 · 외계인 캠프 · God-사료 낙하)
- 상자 상호작용(1.5초 채널링, 피격 시 취소 여부는 기획 미정)
- 배회형 스폰 — 플레이어 반경 40유닛 내 적 수를 목표치로 유지
- 200×200 맵 경계 + 지역 3구역

**3순위 — 개별 노드**
- 스킬별 치명타 확률/피해 오버라이드 (현재 치확·치피는 캐릭터 스탯)
- 버프 `InstantHeal` (현 EBuffType 에 없음), `DamageReduce`
- 디버프 `Knockback`, `Taunt`, `Reveal`
- 타겟팅 `TargetRadial`(코기), `TargetNearestBackward`(꼬리 채찍), `TargetHighestHp`(제3의 눈)
- 이동 궤적 장판 (그레이하운드)
- `DespawnAfterBounces` 구현 (현재 config.UnimplementedNodes)
- 스킬 데이터 `displayName` 분리 (현재 `name` 이 기능 키 겸 노출명)
- 파츠에 `부위` / `유저 공용·캐릭터 고유` 구분 필드
- 도감 해금 상태 세이브 데이터 (유저 귀속, 전 캐릭터 공유)

**성능 (밸런스보다 먼저)**
- 12분 시점 주변 적 120마리 목표. 회차 1 실측은 49마리에 FPS 49(에디터).
  **풀링·컬링 선행 없이는 밸런스 실측 자체가 불가능**

## 주의

- 「개수」 특성은 파츠마다 의미가 다르다 (투사체 / 동시 설치 / 연쇄 대상 / 낙하지점).
  `ModifySkill` 이 고칠 파라미터 키를 파츠 데이터에 명시할 것 — 증강 쪽에 하드코딩 금지
- 카드 레벨이 올리는 「대표 수치」도 파츠마다 다른 키를 가리킨다 (피해 계수 / 이속 증가폭 / 보호막량).
  마찬가지로 데이터에 키를 적고 로직에 분기를 넣지 않는다
- 버프·유틸형 파츠(우다다·개쌘놈·보호막·하품)는 피해 특성이 없다. 옵션 생성 시 자동으로 빠진다
- 파츠 드랍 시 옵션 추첨은 **그 파츠에 존재하는 특성 중에서만** 뽑는다. 중첩 한도 초과분은 재추첨
