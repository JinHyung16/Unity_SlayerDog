### 규약
- **한 폴더 = 한 스킬.** 파츠 27 ↔ 스킬 27 은 1:1, 옵션 159는 전부 파츠 하나에 귀속
- **Master 는 Visual 을 이름으로 가리키지 않는다. 파일 이름이 곧 연결이다** (`Master/<이름>` → `Visual/<이름>`).
  적게 두면 어긋날 수 있고, 어긋나면 조용히 남의 그림이 나간다
- **Method 만 이름으로 가리킨다.** 발사 방식은 재사용이 본질이라 9종을 27개가 나눠 쓴다
- `config.json` 의 `folderOnly: true` — 파츠·옵션은 스킬 폴더에서만 온다.
  제네릭 스캔을 돌리면 같은 폴더의 `skill.js` 까지 파츠로 집는다
- id 표 검사는 폴더 것을 합친 **뒤에** 돈다. **검사를 건너뛴 데이터는 검사가 없는 것보다 나쁘다**
- 공유하지 않는다. 복붙이 목적이면 공유보다 복제다 — 공유는 남의 스킬을 건드릴까 봐 못 고치게 만든다

## 런타임이 실제로 읽는 것

`Assets/Resources/GameData/*.json`. 런타임은 `Skill.json` 과 id 표만 읽고 **id 로 조인**한다 —
`SkillVisual/Method.json` 을 C# 에서 여는 곳은 없다.

## 미구현 노드 — 문서에 적지 않는다

`_DataExporter/config.json` 의 `UnimplementedNodes` 가 SSOT 이고,
**Jinhyeong/GameData/스킬 노드 어휘 검사** 가 실제 코드를 스캔해 갱신한다.
현재 3종: `TriggerOnOreBreak` · `DespawnAfterBounces` · `DespawnOnWall`

- 노드 클래스는 `[BTNode(ESkillNodeType.…)]` 로 **자기 타입을 스스로 신고**한다.
  `BTNodeRegistry` 가 리플렉션으로 수집하므로 switch 를 고칠 일이 없다
- **받는 것 ≠ 동작하는 것.** 클래스는 값을 받지만 아무도 안 읽는 노드는
  어트리뷰트의 `Inert = new[]{ … }` 로 따로 표시한다

## 파츠의 두 레벨 (혼동 주의)

| | 무엇 | 저장 | 적용 |
|---|---|---|---|
| 파츠 카드 레벨 | 아웃게임 영구. 런 시작 수치를 올린다 | 세이브 (유저 귀속) | 기본 파라미터 배율 |
| 파츠 옵션 | 런 한정. 주운 개체에 붙어 있다 | 런 종료 시 폐기 | `SkillModifier` |

적용 순서 고정: `기본값 × 카드레벨 배율 → 파츠 옵션`. 반대로 하면 곱연산 결과가 달라진다.
카드 레벨 최대 Lv15, `기본값 × (1 + 0.08 × (Lv-1))` → Lv15 = 2.12배.

`SkillModifier` 의 적용점은 `SkillNodeData.GetFloat/GetInt` **한 곳뿐**이다.
공유물인 노드 데이터에 값을 굽지 않고 조회 시 곱해서 내보낸다 —
발사체는 `SkillConfig` 가 보정을 들고 있어 날아가는 중에 파츠를 바꿔도 그 탄은 안 변한다.

## 데이터에 키를 적고 로직에 분기를 넣지 않는다
- 「개수」 특성은 파츠마다 의미가 다르다 (투사체 / 동시 설치 / 연쇄 대상 / 낙하지점)
- 카드 레벨이 올리는 「대표 수치」도 파츠마다 다른 키를 가리킨다 (피해 계수 / 이속 증가폭 / 보호막량)
- 버프·유틸형 파츠는 피해 특성이 없다. 옵션 생성 시 자동으로 빠진다
- 파츠 드랍 시 옵션 추첨은 **그 파츠에 존재하는 특성 중에서만** 뽑는다
